# 两行缓存与 3×3 窗口：小图和 720p 验证

用户的分工是图像处理 A，对应验收 ZIP 中按职责命名的 B3。目前已完成窗口的小图和连续两帧 720p 行为验证，以及 TD 两行 RAM 映射检查；正式交付与板级适配仍待完成，还不是完整 B3 验收。

`window_3x3.v` 接收一个时钟周期一个 8 位灰度像素，记住前两行和当前列左侧的两个像素，输出完整的九像素邻域。没有接入灰度模块、Sobel 或显示选择器。测试直接生成灰度输入，便于单独定位窗口问题。

## 接口与数据排列

- 参数 `WIDTH`、`HEIGHT` 范围均为 3～2048，默认 16×12；运行期间不可改变。
- 输入 `in_valid`、`in_gray[7:0]`、11 位 `in_x/in_y`、`in_sof/in_eol/in_eof` 和 32 位 `in_source_frame_id` 沿用现有单像素流草案。上游保证坐标从 (0,0) 开始逐行递增，标记与像素对齐，帧内来源 ID 一致；无反压。合法输入每行连续，行间和帧间空白可变，也验证了完全无空白的连续帧。
- `out_window[71:0]` 从高字节到低字节依次为 `p00,p01,p02,p10,p11,p12,p20,p21,p22`，排列如下。每个像素都是 8 位灰度值。

```text
p00 p01 p02
p10 p11 p12
p20 p21 p22
```

只有已接收的输入坐标满足 x≥2、y≥2 时才产生完整窗口；对应 `out_center_x=x-1`、`out_center_y=y-1`。输入像素位于窗口右下角 p22，而 p11 才是窗口中心。

`out_sof` 标记首个完整窗口，中心为 (1,1)；`out_eol` 标记该窗口行的最后一个中心，x 为 WIDTH-2；`out_eof` 标记最后一个完整窗口，中心为 (WIDTH-2,HEIGHT-2)。这些标记描述的是缩小后的内部窗口流，不能直接当作完整 HDMI 光栅。`out_source_frame_id` 保留来源 ID。

无效周期所有输出字段为零。每帧仅输出 `(WIDTH-2)*(HEIGHT-2)` 个窗口；第一、最后一行/列的边界处理和完整画面恢复留给后续阶段。

## 存储和延迟

使用两组 WIDTH×8 位数组。两组数组都同步读取当前列；下一拍再把当前灰度写入第一组、把刚读出的上一行灰度写入第二组。合法光栅中相邻有效像素的列地址不同，因此有效历史读取不依赖同地址读写时的厂商模式。数组本身没有复位循环。2026-10-04 已通过 TD 确认 1280×720 配置映射为两块 ERAM20K，详细范围见文末综合记录。

| 时钟边沿 | 操作 |
|---|---|
| E_n | 接收像素 (x,y)，同步读取两组历史数据，并寄存当前灰度和元数据 |
| E_(n+1) | 写回这一个像素的历史，结合左侧两列生成窗口，同时输出中心坐标和帧号；也可接收下一个像素 |

从输入到窗口输出有两级寄存器：在 E_n 采样的输入，其对应窗口在 E_(n+1) 更新，不是同拍输出。输入在下降沿驱动时，10 ns 的测试时钟下，输入变化到输出变化相隔 15 ns；这只是行为仿真时钟，不是已确定的硬件频率。

首个窗口需要先接收两整行和第三行的前三个像素，即第 `2*WIDTH+3` 个有效输入，再经过上述输出边沿。因此窗口建立时间包含两行历史及行间空白，不能只说“延迟两拍”。完整帧最后一个像素在 E_n 接收后，最后窗口在 E_(n+1) 输出，不需要额外输入补零；期间时钟必须继续运行。

## 复位规则

低电平异步复位清除接收状态、流水有效位、横向历史和所有输出，不清空两组数组。复位后等待有效 SOF，忽略旧帧尾部。新帧前两行重新建立历史，前两列重新建立横向历史，期间不输出虚假的完整窗口。

已经输出的半帧窗口无法撤回；下游不能把它作为完整帧。输入坐标/标记的合法性由上游保证；越界坐标被抑制以避免越界寻址，本模块不负责修复损坏的输入序列。
