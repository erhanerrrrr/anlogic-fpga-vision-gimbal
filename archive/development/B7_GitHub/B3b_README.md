## 一份按键模块，三个独立事件

```text
三路原始按键 ─→ 一份 button_events（每键两级同步 + 独立消抖计数）
                  ├─ bit0 → 请求模式每次+1 → B3a等待有效帧边界 → B2d四模式像素
                  ├─ bit1 → calibrate_evt → A路由给C
                  └─ bit2 → track_toggle_evt → A控制状态机
```

每个按键需要连续N次不同于当前确认状态的同步采样，才改变按下/释放状态。确认按下产生一拍事件；确认释放只重新允许下一次按下，不产生按下事件。低于门槛的抖动被忽略，长按不连发。

模式顺序：0 RAW → 1 GRAY → 2 EDGE → 3 MASK → 0 RAW。累计的是“请求模式”，所以在下一个SOF之前按两次，也会前进两档。不是反复拿尚未更新的当前画面模式加1。

## 接口给A

编译入口 `b3b_sources.f`，只编译明确列出的源，不递归加入历史顶层。顶层 `rtl/video_button_stream.v` 包含一份 `button_mode_request` 和一份B3a像素链；没有第二套消抖，没有新增RGB队列。

像素、C分类配置、身份、输出、FIFO统计和故障端口沿用B3a/B2d。本包装将外部模式请求口换成以下按键口：

| 字段 | 宽度 / 用法 |
|---|---|
| buttons_async | 3，原始按键电平，bit0模式、bit1标定、bit2跟踪启停 |
| pressed | 3，已经同步并消抖的按下状态，1表示按住，与物理极性无关 |
| press_event | 3，确认按下的一拍事件，可同时出现多个位 |
| mode_next_evt | 1，press_event[0]的别名；本包装已内部处理模式切换，用于观察，不能再反馈触发第二次切换 |
| calibrate_evt | 1，press_event[1]，标定请求，不表示采样或计算完成 |
| track_toggle_evt | 1，press_event[2]，跟踪启停请求，不代表云台正在跟随 |
| requested_mode | 2，累计到的请求模式，可能领先当前画面 |
| active_input_mode / next_frame_mode | B3a诊断值，分别是已应用输入帧模式和下个SOF候选；不是显示标签 |
| out_mode | 2，随当前有效输出像素传递；画面标签使用此值 |
| invalid_request / invalid_request_seen | 沿用B3a诊断口；正常按键只能生成0..3，测试要求它们始终为0 |

参数 `DEBOUNCE_CYCLES` 默认750000，必须≥1；`ACTIVE_LOW` 默认1，表示三个物理按键都低有效，设为0则高有效。两种极性均完成仿真。这里只保留原代码参数，**不表示A已经确认板上的极性、引脚或时钟**。三个键共用该极性参数，混合极性板卡需由A明确适配。

消抖时间近似 `N/f_clk`，例如75MHz与750000拍对应10ms。75MHz在此仅是独立综合的暂定约束，A须根据最终像素时钟重新确认N和引脚约束，不要把仿真时钟周期当成板卡实际时钟。

原始电平若在第1个采样沿前稳定，经过两级同步，按下事件在第N+2个沿之后更新；后级在下一上升沿消费它。规则“请求与SOF同拍留到后一SOF”针对**事件被后级采样的那个沿**。联合测试专门把该消费沿与输入SOF重合，验证当前帧不变、后一帧才切换。

三种事件都在本模块clk域。A/C若在其它时钟域，须使用可靠事件握手/FIFO；不能直接把单拍脉冲跨域，也不能再用另一套消抖重复处理同一物理键。两级同步的RTL功能仿真不替代板级CDC与布局/时序检查。

## 同时按键、故障和复位

- 三键相互独立，同时确认按下就同时输出三个事件；本包装不替A/C做标定、跟踪或其它业务优先级仲裁。
- 标定/跟踪键不改变显示模式；C忙时是否忽略标定请求、参数何时生效、云台是否允许启动由对应状态机决定。
- 视频abort、超时等只清图像流水线，沿用B3a的模式保留规则；不会复位按键层，因此一直按住的键不会因视频恢复再次触发。
- 外部rst_n会清按键、请求模式、活动模式和诊断。若释放复位时仍按着键，经过完整同步/消抖后会产生一次新的按下事件；这与“视频abort不重新触发”不同，必须按本契约接入。
- 按下后需完整确认释放才重新触发；短于N的释放抖动不会把长按变成多次按下。

没有新增像素寄存级，四模式输出节奏沿用B3a/B2d。以已验证720p光栅计，首像素延迟1655拍、EOF延迟1285拍，RGB FIFO深度2048×24、峰值1284。B3b没有重新测量720p这些数值，它复用未改的已验证链路。A仍负责HDMI定时/供数、DDR来源和跨域。

## 本次验证

### 默认计数与边界

`tb_button_boundaries.v` 对N=1/4/7/750000各跑高、低有效两种极性，共8组。N=750000时使用真实计数，不强制内部计数器、不缩短参数。

- N−1、N、N+1长度的按下，明确核对两级同步造成的事件延迟。
- 长按超过两个消抖周期只产生一次事件。
- 短释放、完整释放、再次按下，以及1拍交替抖动。
- 三键同时按、各键单独按，按四次模式键回到RAW。
- 外部复位时按住，复位后完整确认并只产生一次事件。
- 每拍检查事件宽度、pressed状态、模式请求值及累计请求模式。

N=1无抖动过滤窗口，因此跳过N−1和抖动拒绝场景，另两种边界仍测；其余N各7类场景。按下事件日志见各用例 `button_events.csv`。

### 按键到真实视频的联合链

`tb_video_buttons_control.v` 用N=4加快场景执行，高低两种极性各9个完整16×12帧，共18帧/3456像素。输入是原始按键电平，没有强制内部press_event。

验证两次按键先于SOF的累计、标定/跟踪独立事件、帧中按键、事件消费与SOF同拍、三键同时按、视频abort期间长按、外部复位时按住。四路候选及所选像素、模式、全部身份、坐标和标志逐像素核对。输出图还由Python独立核对红色原图/灰度值60/均匀图黑色EDGE/真实C白色MASK。
