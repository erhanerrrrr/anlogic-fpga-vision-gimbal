# 当前练习：带坐标和来源帧号的像素直通

这是电脑仿真用的 RGB888 单像素流接口草案，尚未接入板级工程。

| 信号 | 含义 |
|---|---|
| `clk`、`rst_n` | 上升沿采样，低电平异步复位 |
| `in_valid`、`in_rgb[23:0]` | 每个有效周期一个像素；R、G、B 依次占高、中、低 8 位 |
| `in_x[10:0]`、`in_y[10:0]` | 输入像素所在列、行；左上角为 (0,0)，向右、向下递增 |
| `in_sof`、`in_eol`、`in_eof` | 分别与首像素、行末像素、帧末像素同时有效 |
| `in_source_frame_id[31:0]` | 上游提供的来源采集帧号，一张图片的全部有效像素使用同一帧号 |
| 对应 `out_*` | 颜色、坐标、标记、来源帧号和有效信号一起经过一级寄存器后输出 |

坐标由输入源提供，当前由 testbench 生成；`video_bypass` 只传递坐标，不自行计数，也不修正输入的错误坐标。每轴 11 位可表达 0～2047，位宽能容纳 1280×720；当前已覆盖 16×12 小图和连续两帧 1280×720。

复位期间全部输出清零。复位后或收到 EOF 后，只有有效 SOF 才能开始接收新帧；此前的碎片被忽略。无效输出周期的颜色、坐标、标记和帧号均为零。复位前已经输出的半帧前缀无法撤回，下游须按完整帧验收。

来源帧号使用 32 位无符号整数。接口草案约定由采集端为新采集帧递增编号，最大值 4294967295 后回到 0；0 是合法帧号，有效性由 `valid` 判断。显示重复旧帧时保留其原始帧号和内容；显示跳帧时收到的帧号可以不连续。直通模块逐像素原样传递 ID，不在 SOF 处自行生成编号，也不修正同一帧内错误变化的 ID；输入帧号一致性由上游保证。帧号不是时间戳，也不是永久唯一标识。

只复位图像处理模块不应使采集编号重新开始；恢复后使用新 SOF 随带的来源帧号。采集端自身复位后的编号策略需要在板级接口确定时统一。

输入在时钟下降沿改变，输出在下一个上升沿更新；练习时钟周期为 10 ns，因此波形上的输入、输出变化相隔 5 ns。这代表一级寄存器，不能据此认定硬件时钟或板上总延迟。
