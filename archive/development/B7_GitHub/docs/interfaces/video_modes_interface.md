# 多算法切换：四模式小图与 720p 集成

新增 `video_modes.v`，连接已验证的模式控制器和 RGB/边缘配对链，加入灰度分支、测试掩膜和模式选择。已通过四模式小图行为验证、实际 RTL 图片还原与独立比对、10 帧 720p 集成仿真及整链 TD 独立综合检查。正式接口冻结、完整交接和上板仍未完成，不能将这些模块证据当成 B5 板级验收完成。

## 模式与像素规则

| 值 | 显示输出 |
|---|---|
| 0 | 原基础 RGB，逐位不变 |
| 1 | `(77*R+150*G+29*B+128)>>8`，三个通道均为灰度值 |
| 2 | Sobel 二值边缘，默认阈值 128，最终四周强制黑色 |
| 3 | 输入掩膜位：0 输出黑色，1 输出白色 |

模块不新增 Gamma，所有算法针对同一输入 RGB 阶段。当前仿真输入是确定性 RGB 测试图；正式 ISP/Gamma 所处阶段仍需按样例对接接口冻结，不能把这里的图直接当作真实摄像头效果。

输入沿用 clk、低有效异步复位 rst_n、in_valid、RGB888、SOF/EOL/EOF、11 位 x/y、32 位来源帧号，另外增加 `in_mask` 和模式请求。WIDTH/HEIGHT 范围 3～2048，默认 16×12；THRESHOLD 默认 128。每个有效周期一像素，行内连续，行间/帧间可空白，无反压。

`in_mask` 与本拍 `in_rgb` 共用坐标、标记及来源 ID，必须描述同一像素。当前来自独立棋盘格测试发生器，不是颜色识别结果。真实 C 模块若产生延迟不同的掩膜，需在上游将 RGB/掩膜匹配成此输入包；不能直接把延迟掩膜接到当前拍的 RGB 上。

输出 `out_rgb` 为选中画面，`out_mode[1:0]` 标明这个输出像素属于哪个显示模式；其余输出为 valid、坐标、SOF/EOL/EOF、来源 ID，以及粘滞 `out_error`。所有无效像素字段和 out_mode 清零。out_mode 在有效帧内固定，来源 ID 原样保留、不按显示切换重新编号。

## 请求与帧绑定

`mode_req_valid` 和 `mode_req[2:0]` 是像素时钟域内的请求事件，不直接连接异步按键。

- 合法值 0～3 写入 pending；同帧多个合法请求取最后一个。
- 下一有效输入 SOF 采用此前 pending。请求与 SOF 恰好同拍时，该请求留到再下一有效 SOF。
- 非法值 4～7 被忽略，`invalid_request` 在采样后置 1；下一拍没有非法请求时清零。此前合法 pending 保留。非法请求不使图像通路的 out_error 置位。
- 复位恢复模式 0，清除 pending 和缓存有效状态；忽略没有 SOF 的残帧片段。

每个接纳的输入像素把 `{该帧模式,mask}` 写入独立 3 位标签 FIFO，深度 `4*WIDTH+16`。首像素使用 `mode_for_sof`，后续像素使用 active_mode。标签随后跟随同一个来源像素出队，不能用“当前输入模式”选择较早帧的输出。

在 RGB/边缘配对结果到达时，同步读取标签 FIFO，并同时计算灰度、打一拍原图/边缘及元数据。各分支在同一拍选择：原图、灰度、边缘、mask 均属于同一像素。标签 RAM 不整体复位，valid 和指针屏蔽旧内容。原 81 位配对 FIFO 与算法模块均未修改。

`out_error` 汇总配对链错误和标签 FIFO 上溢/下溢，并保持到复位。不提供错误后自动补帧。正常测试始终要求错误标志为 0；输入非法序列不属于可自动修复范围。

## 延迟及识别支路

四模式输出都比 `video_rgb_edge_align` 多一拍：无空白输入的 SOF 延迟为 `3*WIDTH+6` 周期；输入前两行后的空白 B0/B1 再加到这一值上。输出行间空白由边缘链调度，不能把所有像素当作固定拍延迟。测试逐帧约束 EOF 冲刷不超过 `6*WIDTH+20` 周期。

`detect_*` 是与显示模式无关的基础 RGB 观察支路，使用既有 `video_bypass`，数据、坐标、标记和 ID 一起经过一个输出寄存器级。每拍与采样到的合法输入包比较，包括显示切换和非法请求期间；识别数据不取自已灰度化或边缘化的显示输出。

此支路用于验证“显示切换不改基础 RGB”这一约束。本步没有实例化真实 C 模块；真实集成可以在上游先分出基础 RGB 给 C，再将用于显示的 RGB 与 C 的掩膜延迟对齐。不能假设直接从本模块 detect_* 接 C，再把延迟后的掩膜接回未延迟的 in_mask 就能对齐。

异步复位会清输出、标签队列、模式状态和各分支有效状态。已输出的半帧无法撤回，下游丢弃没有 EOF 的半帧；启动和帧中复位后均重新等待 SOF。
