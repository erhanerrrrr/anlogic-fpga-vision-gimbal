# 多算法切换第二步：原图与边缘对齐

本步新增 `video_rgb_edge_align.v`，同时输出同一来源帧、同一坐标的原图 RGB 和边缘 RGB。它实例化已经通过验证的完整 `video_edge`，并缓存原图以匹配边缘输出节奏。尚未连接模式控制器、灰度选择或分割掩膜，不代表 B5 四模式整层通过。

## 接口与缓存

输入仍为 clk、低有效异步复位 rst_n、valid、RGB888、SOF/EOL/EOF、11 位 x/y、32 位 source_frame_id。参数 WIDTH/HEIGHT 支持 3～2048，默认 16×12；THRESHOLD 默认 128。合法输入逐行扫描，行内连续有效，行间与帧间可有空白，也可完全无空白；无反压端口。

输出有两路数据 `out_original_rgb` 和 `out_edge_rgb`，共用 `out_valid`、SOF/EOL/EOF、x/y 和来源帧号。所有无效输出字段为零。原图逐位保持采样到的 RGB，不做 Gamma、颜色调整或坐标移动；边缘沿用原公式和四周最终黑边规则。

FIFO 每项保存 81 位：原始 RGB24、SOF/EOL/EOF3、x/y22 和来源 ID32。深度为 `4*WIDTH+16`，存储量随行宽增长，不是整帧缓存。保留完整元数据是为了在硬件中核对配对关系，代价比只存 RGB 大；不能把这个阶段的缓存开销漏掉。

1280 宽时有 5136 项、416016 位逻辑存储，约 50.8 KiB，另外仍有边缘链内部缓存。后续 TD 已确认新增 FIFO 使用 23 块 ERAM20K，加原有边缘链共 26 块；不能直接套用此前边缘链的 3 ERAM20K 结论。独立综合结果详见下节。

接收到合法帧的像素时写 FIFO；每收到一个完整边缘流的有效输出，就读取 FIFO 最早的原图像素。同步 RAM 读取与边缘像素、坐标、标记、ID 的一个寄存器延迟并行，最终两路同拍输出。缓存数组不整体复位，复位清指针、数量和 valid，以 valid 屏蔽旧 RAM 内容。

复位后和 EOF 后忽略没有 SOF 的片段，与 `video_gray` 的接纳规则一致。源帧 ID 不重编号。复位打断的半帧不能撤回，下游仍需丢弃没有 EOF 的半帧。

`out_error` 是复位清零的粘滞诊断，检查边缘链错误、FIFO 上溢/下溢，以及读出的原图元数据是否与配对边缘一致。元数据比较在配对结果产生后的下一拍记录；出现错误后不能把受影响帧当作正常画面，需复位重建状态。本模块不保证修复非法视频流。满 FIFO 时即使同时读出也不写入，避免同地址读写的器件相关语义；合法输入测试要求从不达到这一状态。

## 延迟与调度

相对 `video_edge` 的所有输出恰好多一拍。无空白时，输入 SOF 到配对输出 SOF 为 `3*WIDTH+5` 周期；前两输入行后有 B0/B1 拍空白时增加 B0+B1。其他像素不能概括为固定拍延迟，因为边缘光栅会重新安排行间空白。

输出每行连续、每帧 WIDTH×HEIGHT 对像素。输入结束后只需继续给时钟，就能输出剩余结果；测试每帧 EOF 冲刷上限为 `6*WIDTH+18` 周期。没有生成 HDMI HS/VS，也没有冻结真实 HDMI DE 调度。
