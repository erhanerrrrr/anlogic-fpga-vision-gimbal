# 协作与基线规则

1. 当前共同板测基线为 `boards/hx1p35a/h4e/`；以[首页](README.md)、[接口](docs/interfaces/team-contract-v1.md)和[阶段任务](docs/team-roadmap.md)为准。新成员先复现check、unit、pipeline，无板可完成B/C开发。
2. 一人一功能分支，一小阶段一PR，记录起点commit。A负责新板级目录/约束/构建/上板，B维护`B7_GitHub/`，C维护`rtl/recognition/`及对应模型与测试。接口变更需列出A/B/C受影响端点。
3. H4E快照和已验收bit不直接编辑。C后续修改根目录的连通域核，A在新阶段明确导入其commit并重建清单；测试也相应指向新开发源码。冻结基线测试只能证明冻结版本，不能替代新修改的测试。
4. 不递归搜全仓库RTL进行编译。当前B/C与冻结快照存在同名模块，必须使用显式源列表，项目入口在PR中写清。
5. 提交小型摘要、必要参考图和可再生成的脚本。不要提交大型vvp、波形、逐像素CSV/mem、工具安装目录、个人手机素材。H4E bit是一次性验收基准，后续发布bit优先使用关联commit的发布资产，并记录SHA256。
6. 验证等级分别写：软件参考通过、RTL仿真通过、独立综合通过、完整板级时序通过、用户板测通过。不可互相替代。本仓库记录的历史结果不是你本次运行的结果。
7. 不force push共享分支、不覆盖队友未合并改动、不擅改默认分支。新共同基线经PR评审/合并后发布。保留官方IP与队友归属；不为整个仓库添加未经确认的统一开源许可。

PR模板见`.github/pull_request_template.md`。接入代码前先跑受影响测试，板级变更还需资源、布线时序和针对性板测；不要求每次文档更改重做所有上板步骤。
