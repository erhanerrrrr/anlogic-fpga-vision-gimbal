## 本次修正

H4D实拍出现白区仍在、T V=0/E=3/L=20、绿框消失。L=20是十六进制32，表示累计临时编号耗尽；一个多分支目标也可能产生许多临时编号。H4D上板未通过。

H4E按行提取连续白像素段，执行精确8邻域连通域归并。每行结束后压缩和回收编号，仅将仍接触该行的区域传给下一行。已结束区域参与最大区域快照，不再占用活跃编号。区域记录和三份行游程列表使用同步RAM，统计运算由顺序状态机共享，避免扩大原版寄存器阵列。不增加整帧图像缓存。

- 每行最多64个白色游程，工作记录最多128个；这不是整帧目标数上限。
- 区域记录采用两组交替工作，归并使用按秩合并，限制父节点查找深度。
- 每个行任务必须在下一输入行结束前完成；超时拒绝该帧，下一帧可恢复。
- 保留最大8邻域区域，面积至少256；中心为包围框中点。等面积时先选ymin较小者，再选xmin较小者。
- 红色阈值24/16/16、上下4行保护、3×3五票滤波、亮度链路、Logo和视频像素延迟保持原配置。不设75%填充率门槛。
- Logo不透明像素改为覆盖目标框/十字，防止大范围诊断框经过右上角时遮挡Logo；Logo图案、位置、尺寸不变。

## 屏幕诊断

标题应显示 `H4E ROW RECYCLE R64`。

绿色框/青色十字以及T行描述选中的最大区域。R/F/D仍是全局诊断，F或D可以覆盖多个分离物体，不能用其宽高判断绿框是否错误。黄色固定框是ROI。

T的C改为3位十六进制，表示整帧连通域数量，超过FFF饱和显示；L为2位十六进制，表示本帧峰值工作记录数，已改为逐行回收。L=20本身不再意味着失败。错误帧C=000代表计数不可用，不代表没有白区。

| E | 含义 |
|---|---|
| 0 | 最大区域有效 |
| 1 | 没有滤波后候选像素 |
| 2 | 最大区域面积不足256 |
| 3 | 单行游程或工作记录容量超限 |
| 4 | 显示快照未就绪或帧标识不匹配 |
| 5 | 行处理未及时完成，或内部根查找保护触发 |

无效时T面积、坐标归零，绿色框和青色十字消失。N正常为010000，是固定ROI像素计数，不是帧率。帧标识仍来自HDMI刷新，尚不检测相机采集停帧。

BitWriter选择已识别器件，操作为 **PROGRAM_SRAM**，下载频率 **5 MHz**，点击 **Run**。本次使用SRAM临时下载。

1. 确认标题为H4E。复用出现问题的桌面和红盒场景，静止、平移、倾斜红盒：有足够白区时T V=1/E=0，绿框包围最大白色连通区域。
2. 在远处分开放更小的红物体：形成第二白区后，绿框应留在较大的区域，不能被分离小块拉成跨两物体的大框。
