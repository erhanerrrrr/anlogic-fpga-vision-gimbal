# 对照赛题，用直白的话说明我们已经上板完成了什么

截至2026-10-10，当前认可的上板版本是H4E。依据是用户现场反馈、冻结源码/bit、仿真日志及TD报告；本文不把仿真通过当作新一次实物验收。

一句话：**我们的板子已经能看摄像头画面，从中找出符合当前红色规则的最大有效区域，算出它的位置，在显示器上画框并显示信息；让摄像头跟着目标转动的双轴云台闭环还没有完成。**

## 一、现在板子实际在做什么

### 1. 摄像头的图像已经能进入FPGA，再送到显示器

摄像头通过MIPI把图像送到开发板；工程里的接收、图像处理/缓存、显示输出链路能够运行，最后通过HDMI看到画面。这解决的是整个项目最基础的问题：“摄像头看见的东西，板子能接收和处理，并显示出来。”

我们沿用官方例程/IP建立这条基础链路，再加入队友模块和自编集成逻辑。不能说MIPI、DDR、HDMI的所有底层模块都是我们从零写的，但我们确实把自己的处理功能接进了可运行的板级系统。

之前已经分阶段验证过旁路和灰度显示；当前冻结H4E主要展示二值化诊断画面。不能把不同阶段分别跑过，表述成“当前同一个bit已支持按键切换全部模式”。

### 2. FPGA已经能够按颜色把候选区域挑出来

FPGA逐个检查像素的红、绿、蓝数值。当前设置是：红通道至少24，而且比绿、蓝各高至少16。满足条件的像素成为候选前景。

显示器上看到的白区，可以理解成“这些地方符合当前的红色判断规则”；黑区表示不符合。这里没有让电脑替板子算识别，分类逻辑在FPGA里运行。

但它识别的是颜色特征，不认识“红盒子”这个物体类别。只要另一个物体的像素满足同样条件，也可能被当作候选。光照、反光、颜色接近都可能影响结果；没有完成“任意物体识别”。

### 3. 定位前会先减少小噪声的影响

之前远处的小白点会把目标框拉得很大，因为旧的统计方式可能把多个分离前景当成一个整体计算最外边界。

现在用于定位的mask先经过3×3邻域过滤：周围9个位置中至少5个为前景，才保留该位置。这样孤立点、部分细线和很小的碎点更容易被消掉。检测支路还保留上下各4行的保护屏蔽，避免已知边缘残留影响定位；上游残留原因仍待继续定位。

**当前屏幕显示的是原始分类mask，定位使用的是过滤后的mask。** 因此屏幕上仍看到一些小白点，而绿框没有把它们包进去，可能正是正常效果，不意味着过滤未工作。

过滤不能保证消除所有噪声，也可能削掉小物体边缘，所以后续需要用真实输入继续评估。

### 4. 已经能从多个分离候选区域中选出一个主目标

可以把白色像素想象成地图上的岛。相邻的白点，包括斜着接触的白点，属于同一个岛。系统分别统计这些岛，选出面积最大的一个，并要求过滤后的面积至少256个像素。

所以现在的行为是：画面同时有大、小两个合格红色区域时，绿框只框大区域；移走大区域，如果小区域仍满足门槛，就改为框小区域。这是你已经反馈通过的测试。

这解决了“所有红点一起撑大一个框”的主要问题，也解决了旧区域编号方案在复杂场景下耗尽后让框间歇消失的问题。H4E会逐行回收不再需要的工作记录，减少资源占用。

它仍有明确边界：如果两个同色物体粘在一起，被判成连通区域，可能会合成一个目标；如果突然出现更大的同色物体，主目标可能切换过去。当前策略是每幅图选择最大区域，不保证一直锁定最初那个物体的身份。

### 5. 已经能告诉后级“目标在哪里、有多大”

选出主目标后，系统计算：

- 目标是否有效；
- 前景像素面积；
- 最左、最右、最上、最下坐标；
- 包围框中心坐标；
- 如果无效，是空画面、目标太小，还是算法容量/时间限制导致拒绝。

左上角是(0,0)，往右X增大，往下Y增大。中心是框两边坐标的平均值向下取整，不是按每个像素求出来的质心。

这些数字是以后控制云台需要的输入。举例：目标中心在画面中心右侧，水平控制器会根据偏差和安装方向，给舵机一个让误差减小的命令。**目前已经得到位置数据，但这段舵机反馈控制还没有完成上板。**

### 6. 已经把结果画在屏幕上，并保留安路Logo

绿色框表示选中的主区域，青色十字表示其中心。文字显示版本、目标和诊断信息。Logo也在画面里，并且已经处理目标框/十字覆盖Logo的问题：Logo不透明像素优先显示。

屏幕上的几类数字不要混淆：

| 字段 | 直白含义 |
|---|---|
| R | 原始颜色分类得到的全部候选点统计 |
| F | 过滤后全部候选点的统计，可能包含多个分离区域 |
| D | 根据F计算的全局框/填充率诊断 |
| T | 最后选中的主目标，绿框和青色十字使用它 |
| N=010000 | 十六进制65536，即固定256×256诊断区域的像素数；不是帧率，也不是颜色标定成功计数 |

因此F或D覆盖很宽，不一定说明主目标绿框错误，判断选区要看T。当前文字/框按显示帧边界更新，使用先前已完成的结果，不保证与当前显示图像毫无时间差。

### 7. 指定场景中的消失、接替和恢复已经验收

你已经确认：目标框不再间歇消失；大小目标同时存在时仅框大目标；大目标移走后合格小目标接替；清空画面后结果清零；重新放入目标后恢复；指定连续运行观察没有新增花屏/黑屏问题。

这里的“恢复”是视觉检测恢复。还不能把它说成“云台丢失保持与重新捕获已完成”，因为后者还涉及舵机命令、超时、确认帧数和机械运动。

## 二、这些成果分别对应赛题哪一条

依据用户提供《安路.pdf》物理页16–18的赛题二2.3–2.6；页脚编号重复，因此按PDF物理页定位。

| 赛题要求 | 我们已经完成的具体事情 | 当前结论 |
|---|---|---|
| 2.3(1) MIPI采集、HDMI实时显示 | 摄像头到开发板再到显示器的链路运行，自编处理已进入链路 | 基础功能已有板测；实际新采集帧率和端到端时延未量化 |
| 2.3(2) FPGA至少一种图像算法并显示 | 当前H4E有颜色二值化；检测支路有过滤及定位；此前灰度单独阶段验证过 | 已覆盖“至少一种”的基本算法要求 |
| 2.3(3) 处理画面连续、无明显异常 | 当前阶段指定场景和约一分钟连续观察通过 | 阶段通过，长期与更多环境证据待补 |
| 2.3(4) OSD图文及安路Logo | 目标框、中心、文字、诊断和Logo已经显示 | 已有板测成果；以后还要完善模式/标定/机械状态显示 |
| 2.4(2) 简单目标检测及结果标注 | 红色最大有效区域、位置/面积、框/中心及无效状态 | 已形成扩展功能成果；不是通用物体识别 |
| 2.4(3) 结合实际应用进行外部控制 | 已生成适合后续控制的位置数据 | 视觉前端完成阶段验证，舵机/云台应用尚未闭环 |
| 2.4(4) 优化实时性和资源 | H4E逐行回收区域记录、RAM保存、共享运算；有资源及时序报告 | 有工程优化证据；实际帧率、时延和机械跟踪指标待测 |
| 2.5(1) 按键多算法切换 | B已有独立代码与验证 | 当前H4E未集成全部模式，不能算已上板完成 |
| 2.5(2) 目标动态跟踪、坐标叠加 | 移动物体时画面中的位置和框能跟着更新 | 已有视觉位置跟随基础；固定身份跟踪与机械跟随不能一并宣称完成 |
| 2.5(3) 采集到显示延迟可视化 | 仿真已有局部周期统计 | 真实端到端测量和显示未完成 |
| 2.5(4) 硬件运动检测 | 还没有帧差等运动检测 | 选做；红物体移动时能框住不等于实现帧差 |
| 2.5(5) 自动图像质量调节 | 之前用固定亮度/颜色补偿改善画面 | 允许的画面改善，不等于自动曝光/自动白平衡闭环已验证 |
| 2.6 长时间无花屏、无缓存溢出、剧烈光照变化时正常 | 有短时指定场景验收 | 尚需长期、缓存异常监测、光照突变及恢复测试 |

基本要求不是必须做三种算法；进阶项也不是全部必做。我们的简介已经承诺灰度、边缘、颜色分割、多模式、标定和双轴控制，因此这些仍应作为后续计划落实，不能因为是选题扩展就从项目交付里省略。

## 三、目前哪些证据是板测，哪些只是仿真/工具验证

**实物证据：** 以上指定场景来自用户现场反馈，H4E最终记录约一分钟连续观察。之前其它版本更长时间运行的记录，不能自动算给H4E。现阶段不能保证所有背景、所有灯光和任意长时间都稳定。

**RTL仿真证据：** 68个区域案例、13帧完整720p链路已通过，包含复杂分支、小块干扰、最大区域、超容量/超时、清空和恢复；完整链路检查滤波、显示、Logo及快照等。这证明设计在这些输入下符合预期，不等于真实场景准确率100%。

**原已验收bit的工程证据：** 12,348 Slice、45 ERAM、8 DSP；路由后setup +0.235ns、hold +0.020ns。与此前未通过板测的H4D相比少5,145 Slice，说明修复没有靠简单扩大寄存器硬堆。时序只覆盖现有约束，STA覆盖94.10%，还需要约束/CDC审查。

仓库迁移后又完整构建了一次，得到12,253 Slice、45 ERAM、8 DSP，且现有约束下时序通过；该新bit没有上板，所以没有替换原验收bit。这两个数字属于两次构建，不能混成一份测量或声称只是打包就带来新的算法优化。

## 四、距离“自动跟着目标转动的云台”还差什么

1. **先确认看到的是新图像。** 当前帧号随HDMI刷新增加；如果摄像头停了，显示器仍可能重复旧图。A需要把真实采集ID绑定缓存并加入超时，C保存身份并去重，避免旧目标持续驱动舵机。
2. **让舵机可靠地按命令运动。** A先做独立PWM、型号/供电/方向/软限位，再用假坐标验证死区、限速、丢失保持，之后接真实视觉结果。
3. **先水平，再垂直，再双轴。** 确认运动确实让画面误差减小，而不是越调越偏；测试目标消失、重现、极限和复位。
4. **补完整交互。** B逐项接入原图/灰度/边缘/掩膜、按键和状态；C按采样→参数计算→按帧应用完成标定。
5. **补正式指标与压力证据。** 长时间运行、亮暗突变、缓存异常、真实新帧率、采集到显示时延、静态/动态误差和丢失重获时间，各自说明测量方法与样本数。

目前适合对外这样介绍：“已在安路HX1P35A上实现实时视频处理与颜色主目标定位，支持去噪、最大连通区域选择及目标信息叠加，完成目标接替、清空恢复和阶段连续性验证，正在接入双轴执行机构及完善交互、时延和长期稳定性测试。”
