# C4：中心坐标和完整结果包

2026-10-05；接口 c4-draft-1。独立算术、完整帧与 C1–C3 回归已通过，累计 TD 综合通过。共同接口尚待 A/B 确认，未上板。

## 本步行为

在 C3 原始包围框上求中心：cx=floor((xmin+xmax)/2)、cy=floor((ymin+ymax)/2)。两个坐标先各加一位再求和，取高位实现除以 2，避免溢出并向下取整。

暂用 raw_count>0 作为 target_valid。无目标仍发一个结果，target_valid=0，area、中心和四边界全部为 0；帧号、参数版本、指定颜色仍对应本帧。此规则仅用于验证算术和接口，不能作为最终抗干扰或多目标选择策略。

## 模块与连接

- target_result_pack.v：从一组已锁存的原始统计生成结果包。
- mask_target_result.v：C3 统计 + 参数标识关联 + 结果打包；适合接 B/C 共享的 C2 掩膜支路。
- rgb_target_result.v：C1→C2→C3→C4 的完整演示连接，输入 RGB、输出结果。
- 累计源文件列表为 rtl/recognition/c4_sources.f；不包含 testbench 或仅用于综合的外壳。

C2 原有掩膜接口保留。B 如需同时显示掩膜和目标框，可从同一 C2 实例分支，将掩膜一路用于显示、一路接 mask_target_result。rgb_target_result 的掩膜当前为内部连线，不是额外对外显示端口。

## 对 A/B 的结果接口

| 字段 | 默认宽度及含义 |
|---|---|
| result_strobe | 1 位，本周期整个结果包有效更新；每个完整帧一次 |
| target_valid | 1 位，当前临时规则为面积大于 0 |
| result_frame_id | 32 位，对应公共协议的来源帧号 source_frame_id |
| result_cfg_id | 16 位，对应公共协议 cfg_id，预设阶段正常使用 0 |
| target_id | 2 位，0 红、1 绿、2 蓝，与本帧指定颜色一致 |
| area | 20 位，目标像素数，覆盖 720p 全图 |
| cx、cy | 各 11 位，包围框中心 |
| xmin、ymin、xmax、ymax | 各 11 位，含两端的包围框 |

结果包的全部字段在同一个上升沿后更新，之后保持至下一结果或复位。复位同时清空通知及字段。连续 1×1 帧可以在相邻周期分别发布，strobe 会连续为 1；接收方必须按有效周期接收，不能只检测上升沿。

A 读取 result_strobe 后按 target_valid 使用坐标；无目标包也必须接收，不能沿用旧有效坐标。B 可将整包存入 pending，在其显示 SOF 再整体更新，避免画面中途改框；这属于 B 的显示接口处理。

## 帧参数关联

active_color、cfg_id 是外部已经生效的配置，每帧期间必须保持不变；本步未实现按键、标定或参数生成状态机。正常初始 cfg_id=0，非零值测试只用于验证版本标签不串帧。

mask_target_result 在 SOF 保存颜色和版本，在 EOF 将它们与 C3 原始统计一起锁存，随后由 packer 发布。RGB 顶层先把颜色/版本标签与 C2 像素寄存级对齐。即使下一帧 SOF 已到、其配置已改变，上一帧结果仍使用上一帧标签。

C3 原始统计继续保留在 stats 模块自己的 raw_* 寄存器中，可在仿真/调试层级查看；C4 对外只发布规范结果，不修改 C3 原始数据。未来 C6 的拒判及调试原因接口另行扩展。

## 实测延迟及吞吐

将“末像素被输入接口采样的上升沿”记为 E：

| 接口路径 | 发布时刻（寄存更新后） | L_result |
|---|---|---|
| 原始统计→target_result_pack | 采样 raw_strobe 的该边沿后 | 一个输出寄存级 |
| 掩膜→C3→C4 | E+1 | 1 个时钟周期 |
| RGB→C2→C3→C4 | E+2 | 2 个时钟周期 |

这里按边沿之间的周期差计数，下游在随后的上升沿采样稳定输出；不要额外把“同一边沿后寄存更新”又算一次等待。TB 的 10ns 时钟下对应 10ns/20ns，仅为仿真时序示例，实际时间由 A 最终像素时钟决定。

每拍仍可接收一个像素，不需要除法器、忙等待或反压。测试中 EOF 后下一拍立即输入下一帧 SOF，上一帧计算不破坏下一帧统计。帧中复位丢弃半帧，从下一完整 SOF 恢复；输入停止不发布旧结果。

## 实际验证

1. 固定帧号 10/11/12：矩形→2×2→空帧，每帧恰好一次通知，各字段匹配。
2. 矩形 (100,80)～(140,110)：area=1271、center=(120,95)。
3. 2×2 框 (10,20)～(11,21)：area=4、center=(10,20)，临时规则下有效。
4. 连续两帧 720p：全图→仅末点。全图 center=(639,359)，末点 center=(1279,719)，帧号 0xffffffff→0 正常保留。
5. 连续 1×1 帧分别使用 cfg=7/8/9、不同颜色，验证旧帧计算期间新配置不会污染结果；空帧几何字段清零。
6. 帧中复位无半帧通知，下一完整帧恢复，停输入保持结果且不重复通知。
7. 独立算术核验证两个 11 位最大坐标 2047 相加、奇数和向下取整、raw_count=0 但输入框非零时对外清零，共 5 个锚点。

共 10 组帧用例，其中 1 个被复位中断；掩膜路径和 RGB 路径各 9 个完整结果，逐字段与独立 Python 数学答案完全一致。两条路径都检查通知时机、字段保持、复位和 X/Z。所有测试输入/独立预期来自 tests/fixtures/c4/cases.json 与 run_c4.py，不从 DUT 输出反推答案。

C1、C2、C3 累计回归均通过；故意把期望中心加 1 时必须失败。

## 运行与交付

```powershell
python scripts/run_c4.py
python scripts/run_c4_td.py
```

需要 Python 3.7+、ModelSim vlib/vlog/vsim，以及综合时的 TD 命令行工具。无第三方 Python 依赖；在临时目录编译，不依赖个人路径。

外部仿真命令超时 300 秒；整帧 testbench watchdog 为 100ms 模拟时间；独立算术核 watchdog 为 10us；综合超时 180 秒。编译失败、超时、未完成、输出不一致都返回非零。

reports/c4/generated/ 保存实际 actual.csv、独立 expected.csv、timing.csv、summary.json、result_trace.vcd、编译/仿真日志和检查器自检记录。波形只截取帧末通知及连续帧切换片段，约 104KB。

已有输出可运行 `python scripts/run_c4.py --check-only` 复查；`--check-only --inject-error` 故意改错中心，应退出 1，不计入正常通过率。

## TD 累计综合及限制

本机 TD V6.2.168116，目标 PH1P35MDG324，脚本速度参数 3。综合整个 C1–C4 链路，采用 synth/c4/c4_synth_top.v 作为仅供综合的外壳：通过 16 位分组读出所有 137 位结果字段，避免内部并行接口被当成超过 160 个物理 IO。该外壳不是正式板级设计，也没有替换 A/B 的并行接口。

综合报告含读出外壳：533 LUT、445 寄存器、0 RAM、0 DSP、0 LATCH。层次资源表保留分类、统计、参数关联和中心打包模块，全部结果字段都接到可观测输出，没有综合成空壳。

关键告警为 122 个顶层逻辑 IO 尚未分配具体引脚。此阶段不做引脚约束、布局布线或实际时钟时序验收；资源含测试外壳且不是布局后的最终值。门级网表/资源/日志在 generated/td/。

A/B 需确认字段宽度、来源帧语义和跨时钟接收方式；固定相机真实定位可归入 H2 关卡，本次没有上板证据。当前也没有去噪、干扰拒判、多目标选择、结果去重或机械控制，不能用本阶段的 target_valid 代表最终可信识别。
