# C5：3×3 二值多数滤波和完整输出

日期：2026-10-05；接口 c5-draft-1。直接掩膜与 RGB 完整链路的仿真、TD 累计综合、C1–C4 回归均通过。公共接口和上板仍待 A/B 确认。

## 算法与范围

对每个内部像素，统计以它为中心的 3×3 邻域：9 个位置至少有 5 个为 1，则输出 1，否则输出 0。最终第一/最后一行、第一/最后一列强制为 0。

这是“最终边界置 0”，不是对补零图像直接做卷积。孤立点会消失，小孔可能被补回；一像素细线也会消失，不能宣称所有细目标都能保留。

本阶段仍用滤波后 count>0 作为临时有效性，不含 C6 的面积、宽高、填充率或干扰拒判。例如 5/9 边界用例最终剩下一个点，C5 下仍为有效；后续 C6 才可能拒绝。

## 模块

- mask_majority_3x3.v：两行缓存、二值多数逻辑、完整帧输出及边界补齐。
- mask_denoised_result.v：直接掩膜→滤波→既有 C3/C4，输出滤波掩膜和结果包。
- rgb_denoised_result.v：RGB→C1/C2→滤波→C3/C4，作为新的完整链路。
- 累计源文件列表：rtl/recognition/c5_sources.f。

原 C1–C4 模块和测试没有改算法或旧期望；C5 的整链期望单独保存，不能再把滤波后的矩形面积写为 1271。

## 输入输出接口

RGB 顶层输入与 C4 相同：clk、rst_n、pixel_valid、rgb、x/y、sof/eol/eof、source_frame_id、cfg_id、active_color。整帧颜色/配置必须固定，由上游管理；本阶段未实现按键或标定状态机。

新增给 B 的输出：filtered_valid、filtered_mask、filtered_x/y、filtered_sof/eol/eof、filtered_frame_id、filtered_cfg_id、filtered_target_id。每个完整帧严格输出 W×H 个像素，按逐行顺序；0→黑、1→白。坐标和帧标记指向滤波后的实际位置，不指向正在输入的邻域右下角。

结果包沿用 C4：result_strobe、target_valid、result_frame_id、result_cfg_id、target_id、area、cx/cy、xmin/ymin/xmax/ymax。统计模块连接 filtered_*，特别是 filtered_eof，不能再连接原 RGB 的 eof。

WIDTH、HEIGHT 是编译期参数，默认 1280×720。当前接口约定 3≤WIDTH≤1280、3≤HEIGHT≤720，固定坐标 11 位、面积 20 位、帧号 32 位、配置号 16 位。尺寸不在帧间动态改变。输入必须是合法逐行坐标、首尾标记，行内连续有效；可以有行/帧空白，也验证了无行间/帧间空拍的最小帧。没有输入反压或错误协议检测。

输出行内也连续有效，行间空白可能与输入不同；B 仍需按自己的显示时序对齐分支，不能原样沿用 C2 的一拍延迟或直接把内部有效流当 HDMI 物理时序。

## 缓存与完整帧调度

两个交替的行 RAM 每个存 WIDTH 个二值位。当前行覆盖两行前的同一行库，RAM 采用同步先读后写，另一个行库保存上一行。6 个横向历史位加本列的 3 个值组成窗口，4 位计数可完整表示 0～9。

RAM 不做整块复位。复位只清控制/输出状态；前两行的不可用历史被坐标条件屏蔽，开始产生内部窗口之前所需存储已被当前帧覆盖，避免依赖 RAM 的初始值。

对内部输出 (x,y)，使用输入 (x+1,y+1) 到达后的窗口。同步读出后下一拍计算/输出。第一行和左边界按同一顺序输出 0。每行尾部主动补一个右边界像素，因此输入行间空白不会成为输出行内空洞。

输入 EOF 后继续输出倒数第二行的右边界和完整最后一行，共 WIDTH+1 个零边界像素。这期间可同时接收下一帧首行；边界尾部不再需要上一帧 RAM 数据，因此不会与新帧写入冲突。上一帧的尾部保存独立帧号、cfg_id 和颜色标识。

启动及帧中复位后丢弃残余帧尾，直到下一有效 SOF。已经输出的半帧不能撤回，下游共用复位丢弃半帧，不发布统计；中断后的 RAM 无需清零即可恢复。输入 EOF 后即使停止送像素，只要时钟继续，已完整输入帧仍会有限地冲刷完；之后不再产生额外结果。

## 实测延迟

以下均按“原输入 EOF 被采样的边沿”到“输出寄存更新后”的周期差计数：

| 路径 | 滤波 EOF | 结果通知 |
|---|---:|---:|
| 直接掩膜输入 | WIDTH+2 | WIDTH+4 |
| RGB 输入（多一个 C2 寄存级） | WIDTH+3 | WIDTH+5 |

720p 对应：直接掩膜 1282 / 1284 拍，RGB 1283 / 1285 拍。滤波 EOF 输出后，C3/C4 再过 2 拍输出结果。所有完整测试帧都测得相同关系，没有使用旧 EOF 提前结算。

整幅画面的像素延迟包含行缓冲和边界调度，不能统一写成“若干拍固定点运算延迟”。例如首输出 SOF 等待输入第二行的第二个像素读出；输入行间空白也影响首输出的周期位置。实际时间由 A 最终时钟频率换算，本阶段不报告真实摄像头 fps 或机械跟踪延迟。

## 独立参考和实际用例

model/c5_reference.py 先生成完整二值图，再用离线数组索引枚举 9 个邻居，独立于 RTL 行缓存和调度。之后从完整参考图计算面积、包围框和中心。tests/fixtures/c5/cases.json 还保存手工锚点数值。

| 输入 | 验证结果 |
|---|---|
| 41×31 实心矩形 | 去掉四角，1271→1267；框和中心保持 |
| 同矩形中心挖一像素孔、远处加孤立点 | 孔补回、远点去除，仍为1267 |
| 单个孤立点、足够分离的点 | 全部消失，结果无效且几何字段清零 |
| 一像素宽长线 | 被削除，作为已知限制记录 |
| 9×7 目标贴左上边 | 按最终边界置零得到47点，框(1,1)～(8,6) |
| 3×3 邻域恰有5点 / 4点 | 5点样例中心保留，4点样例全部消失 |
| 全1后立即输入全0 | 全0帧无旧行残留 |
| 最小3×3全1后全0，无任何行/帧间空拍 | 第一帧仅中心1点，第二帧全0，输出完整 |
| 连续两帧720p：固定种子噪声→全1 | 逐像素通过；全1的外圈置0，area=1278×718=917604 |
| 帧中复位及新完整帧恢复 | 两条路径的已输出半帧前缀分别69/68点，无半帧结果，恢复帧正确 |
| 连续帧切换颜色、cfg及帧号回绕 | 滤波掩膜与结果均保留对应来源标签 |

尺寸覆盖3×3、64×48、640×360、1280×720，共18个用例，17个完整帧及1个中断帧。直接掩膜路径检查2337879个实际像素，RGB路径2337878个；差1来自复位时两条管线多一拍延迟，均符合各自独立预期。每条路径都产生17个完整结果。

640×360 指定矩形仍为 bbox=(100,80,140,110)、center=(120,95)，滤波后 area=1267。完整滤波图、坐标、valid、SOF/EOL/EOF、ID及配置均检查，不是只比较白点总量。

## 如何运行和查看产物

```powershell
python scripts/run_c5.py
python scripts/run_c5_td.py
```

Python 3.7+、ModelSim vlib/vlog/vsim、综合时 TD 命令行工具，无第三方 Python 库。脚本在临时目录运行，干净目录可复现；PNG 编码复用 scripts/run_c2.py 的小工具。全帧仿真外部命令超时360秒，testbench watchdog 为200ms模拟时间；TD 超时180秒。失败、超时或未到完成标记必须返回非零。

reports/c5/generated/ 下按尺寸分目录，保存：

- *_input.png：软件生成的原始掩膜。
- *_rtl_path0.png / *_rtl_path1.png：分别来自实际直连/串接 RTL 输出的滤波图。
- *_diff.png：逐像素比较通过后的差分图，应全黑。
- mask0.hex / mask1.hex：所有实际有效掩膜包；高到低为 mask、sof、eol、eof、x[10:0]、y[10:0]、frame_id[31:0]、cfg_id[15:0]、target_id[1:0]，共76位。
- actual.csv：实际滤波后的目标结果，timing.csv：输入/滤波 EOF 与结果周期。
- filter_trace.vcd、编译/仿真日志、总 summary.json 及干净目录/检查器自检日志。

`python scripts/run_c5.py --check-only` 可重查现有输出；加 `--inject-error` 故意改坏第一个期望 mask，必须退出1。故意错误不计入正常通过率。

## TD 存储和资源检查

TD V6.2.168116，目标 PH1P35MDG324，使用与 C4 相同的分组读出综合外壳，保留全部结果字段可观测。外壳只为综合检查，不是正式板级接口。

| 资源（含各阶段读出外壳） | C4 | C5 | 变化 |
|---|---:|---:|---:|
| LUT | 533 | 713 | +180 |
| 寄存器 | 445 | 678 | +233 |
| ERAM20K | 0 | 2 | +2 |
| DSP / LATCH | 0 / 0 | 0 / 0 | 无 |

日志明确推断2个RAM，门级网表映射为2个 PH1P_PHY_ERAM_V2，写模式 READBEFOREWRITE，与 RTL 同址先读后写要求一致。逻辑行数据为2×1280位，实际占用2块ERAM，不能把有效位数当成物理存储用量。

唯一关键告警仍为122个测试顶层逻辑 IO 未分配引脚。没有布局布线、板级时序或厂商 RAM 门级仿真，上板需由 A 验证；本次完成 RTL 功能仿真与综合推断检查。资源是综合阶段数字，不是最终布局用量。
