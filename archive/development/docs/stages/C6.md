# C6：有效性门槛和指定干扰拒判

日期：2026-10-05；接口 c6-draft-1。独立规则测试和 RGB 完整链路仿真通过，累计 TD 综合完成。公共接口、实际时钟和上板仍待 A/B 确认。

## 判定规则

输入是 C5 滤波后的原始面积和包围框。要同时满足：

- 像素数至少 9。
- 框的宽、高分别至少 3；宽高包含两端，即 xmax−xmin+1、ymax−ymin+1。
- 像素数不超过 MAX_AREA，等于上限可通过。
- 填充率至少 75%，即 4×count≥3×框面积，恰好 75% 可通过。

规则先独立接统计数据验证，再接 RGB→C1/C2→C5→C3/C4 的完整结果。C5 原有暂定结果作为内部输入，C6 再用一个寄存级发布最终有效性；原 C1–C5 模块及隔离测试没有改算法。

## 参数表

| 参数 | 默认值 | 类型 / 生效方式 |
|---|---:|---|
| MIN_AREA | 9 | 20 位无符号编译期常量 |
| MIN_WIDTH / MIN_HEIGHT | 3 / 3 | 12 位无符号编译期常量 |
| MAX_AREA | 完整顶层为 WIDTH×HEIGHT；独立核为921600 | 20 位无符号编译期常量 |
| 最低填充率 | 3/4 | 本版固定整数规则，不提供运行时比例输入 |

640×360 整链测试把 MAX_AREA 设为5000，用于同时覆盖正常小色卡、分散色块和过大区域。720p 用921600。独立核另测100的上限配置，count=100通过、101拒绝。参数是测试基准，实物面积上限还要根据目标大小和距离调整，不能凭本次合成图确定。

WIDTH/HEIGHT 仍沿用 C5 的固定尺寸约定，最大1280×720。改变参数需要重新编译和验证；本步未实现运行时参数提交或标定。

## 原因码与优先级

多项同时失败时按表中从上到下的检查顺序返回第一个原因，只有全部满足才为0。

| 检查顺序 | reject_reason | 含义 |
|---:|---:|---|
| 1 | 1 EMPTY | count=0 |
| 2 | 6 BAD_GEOMETRY | 边界颠倒，或count大于框面积，原始统计不自洽 |
| 3 | 2 TOO_SMALL | 面积小于最小值 |
| 4 | 3 TOO_NARROW | 宽或高不足 |
| 5 | 4 TOO_LARGE | 面积超过上限 |
| 6 | 5 SPARSE | 填充率不足75% |
| 全部满足 | 0 OK | 本版规则通过 |

复位时所有字段清0，strobe=0；不能脱离有效通知，把复位后的reason=0解读为找到目标。

## 模块与结果接口

- target_validity.v：独立组合判据，不使用浮点或除法。
- target_validated_pack.v：判断、结果打包及原始调试字段同步锁存。
- rgb_validated_result.v：C1–C6 完整 RGB 链路，保留 C5 的 filtered_* 掩膜输出。
- 源文件列表：rtl/recognition/c6_sources.f。

原 C4 的结果字段保持同样宽度和含义：result_strobe、target_valid、result_frame_id、result_cfg_id、target_id、area、cx/cy、xmin/ymin/xmax/ymax。

新增 reject_reason[2:0] 和调试字段 debug_count[19:0]、debug_xmin/debug_ymin/debug_xmax/debug_ymax（各11位）。它们与结果包同拍更新并保持，来源帧号和配置版本就是同包的 result_frame_id/result_cfg_id。

拒判仍然发布一次结果，但 target_valid=0，对外 area、中心和框全部清零。debug_* 保留拒判前的真实统计，方便知道“检测到了多少点、为什么不接受”。B 可以显示滤波掩膜和原因，但不能把 debug_* 当成有效目标框交给 A 控制云台。

新门槛不改变掩膜本身；filtered_* 仍是 C5 输出。active_color、cfg_id 仍由上游保证帧内固定，本步不增加按键、标定或机械控制逻辑。

## 位宽与延迟

11位坐标先扩至12位求宽高，能表示2048。宽×高使用24位，比较填充率时扩为26位：count×4和box_area×3都不会在支持范围内溢出。额外测试坐标2047及20位最大count，验证大框不能因溢出错误通过。

判据在一次组合运算中完成，随后结果、原因和debug字段同时寄存。相对于 C5 增加1拍。完整 RGB 链实测：原输入 EOF 到 result_strobe 为 WIDTH+6 拍，filtered_eof 到 result_strobe 为3拍。720p 为1286拍；实际时间取决于 A 最终像素时钟。

每拍仍可接收一个像素，无反压；独立规则模块也测试了连续逐拍统计包。复位清空结果并丢弃半帧，新完整帧恢复；输入停止不重复通知，未通知时整包保持。

## 独立门槛验证

model/c6_reference.py 使用 Python 任意精度整数及 Fraction 做独立数学比较。固定种子20261005，含19个数值锚点、4096组随机统计、空拍、复位，共4150输入周期，两种面积上限合计8300组完整包比较。

主要锚点：

- 3×3、count=9有效；count=8因面积不足无效。
- 宽2、高10、count=20，因宽度不足无效。
- 4×4、count=12恰好75%有效；count=11无效。
- 41×31实心区域count=1271及滤波后1267都通过。
- 两矩形原始count=2542、总框(100,80,340,110)，填充率不足，无效；滤波后2534仍无效。
- 上限100时，100通过、101拒绝；默认上限921600时等于上限通过。
- 极大框、坐标差负值、count大于框面积，以及空统计。

所有原因码0～6均覆盖。默认上限配置的有通知样本中2218个通过、1897个拒绝；上限100配置中8个通过、4107个拒绝。正例和反例同时存在，没有靠全部拒绝获取表面通过。

## 必须保留的能力边界

这不是连通域算法，也不会“始终选择最大色块”。它只检查整张目标掩膜的总体范围和填充程度。

实际反例：红矩形分别位于 x=100..140 和 x=142..182，y=80..110，中间只有一列间隔。C5 多数滤波会连接其中大部分间隔，最终2563点、总框83×31；C6 会判为有效，中心(141,95)。即使不滤波，两个靠近区域也可能满足75%填充率。因此只承诺拒绝已声明的稀疏/分散情况，不承诺可靠发现所有多目标歧义。

需要从多张同色卡中稳定选择一张时，必须另做连通区域分离和目标选择，不能仅继续调高本层阈值。

## 运行和交付

```powershell
python scripts/run_c6.py
python scripts/run_c6_td.py
```

需要 Python 3.7+、ModelSim vlib/vlog/vsim，综合时需要 TD 命令行工具，无第三方 Python 包。临时目录编译运行，无个人绝对路径依赖。外部仿真命令超时360秒；独立核 watchdog为1ms、整链为200ms模拟时间；TD超时180秒。超时、未完成、比较错误和编译失败均返回非零。

reports/c6/generated/ 保存 unit.txt、unit_actual.csv、工具日志、summary.json，各尺寸目录保存实际 actual.csv、独立 expected.csv、filtered_counts.csv、timing.csv、波形和 *_reference_mask.png。本阶段 PNG 明确是参考掩膜，不能冒充实际 RTL 输出图片；C5 的实际逐像素图仍保留在 C5 报告中。

`python scripts/run_c6.py --check-only` 可重查已有输出；加 `--inject-error` 故意翻转期望原因码，应返回1。故意错误不计入正常通过率。
