# C7：连续检测和重复帧去重

日期：2026-10-06；接口 c7-draft-1。本步让每个新的来源帧产生一次检测通知，并验证移动、消失和重现。接口仍待 A/B 确认，未上板。

## 用简单的话说

色卡移动时，输出的中心跟着移动。新的画面没有目标时，明确报告无目标；目标回来后，重新报告它的位置。同一张旧画面重复显示时，仍可生成显示掩膜，但不会反复通知云台“又看到一次目标”。本步没有加入位置平滑或云台动作。

640×360 连续输入；帧与帧之间不等待结果排空。中心坐标从 0 开始计数。

|---|---|---|---|---|

## 接口与规则

新增 `result_new_frame.v`，放在 C6 结果之后；完整顶层为 `rgb_fresh_result.v`。完整顶层端口与 C6 一致，参数和颜色门槛沿用 C6。

- 首次完整结果总是发布，帧号为0也可以。
- 后续只比较来源帧号是否与上次已发布的一样；相同则抑制，不同则发布。有效和无效结果都遵守这个规则。
- 不比较帧号大小，因此32位最大值到0的回绕正常。
- 相同帧号即使候选内容变化，也不更新公开结果包；包括配置号、颜色号、拒判原因和调试字段。切换配置后的新观察必须使用新的来源帧号。
- 只去除连续重复，不保存全部历史。例如10、11、10会发布三次；任意旧帧重放和乱序由上游管理。
- 低有效异步复位清除已见帧标记和结果包。复位后可重新接受相同帧号；整机接入时需要同步释放复位。
- 显示掩膜不经过结果去重，每个完整输入帧仍输出完整的 W×H 掩膜及对应标签。

`result_strobe` 表示新的观察；`target_valid` 只说明最近发布的那份结果有效。停帧时旧的有效字段可能一直保持，A 必须只在新通知到达时刷新超时计时，不能因为 `target_valid=1` 就认为画面仍在更新。目标丢失后的保持、搜索和云台动作由 A 决定。

完整输入帧停止后，流水线可能先正常输出最后一份结果，之后不再产生通知。半帧停止不会凭空生成结果；本测试在复位后用新完整帧恢复，未承诺任意非法中断流可直接续传。不同帧号的真实空画面逐帧报告无目标，不用旧位置伪装目标仍存在。

## 延迟与验证

新增一级结果寄存器：C6 候选到新通知为1拍；从 RGB 输入 EOF 到新通知为 W+7 拍。64、640、1280宽度实测分别71、647、1287拍。重复帧没有新通知；滤波 EOF 延迟仍为 W+3 拍。这是仿真时钟拍数，不是实际板级帧率或时序保证。

独立去重测试4208周期，包含固定锚点、4096个固定种子随机输入及复位/空闲周期，共1285次通知。检查相同帧号但不同数据时整包保持、首帧0、回绕和复位。

完整 RGB 链路有三组：上述8帧序列；64×48半帧复位、半帧停止和恢复；1280×720的最大帧号到0回绕，并改变配置号和目标颜色。共13个完整显示帧、12次新通知，结果包和时序错误均为0。测试检查完整输出光栅、标签、掩膜像素数、所有公开/调试字段、无通知时整包保持。

运行：

```powershell
python scripts/run_c7.py
python scripts/run_c7.py --check-only
python scripts/run_c7_td.py
```

故意错误自检 `python scripts/run_c7.py --check-only --inject-error` 应退出1：检查器必须拒绝“重复帧也发新通知”的错误期望。独立临时目录重新复制必要源文件并重新编译仿真，记录见验收报告。
