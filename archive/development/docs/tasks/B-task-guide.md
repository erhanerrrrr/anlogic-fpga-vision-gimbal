# B 同学任务书：图像处理、画面组织与状态显示

版本：2026-10-10；起点：H4E 已验收视觉定位基线，代码提交 `7eb4a90`。本文件可以单独发给 B 阅读。A 是负责板卡集成和云台的队友，C 负责颜色识别与定位。

## 一、你的目标是什么

你的最终目标是：让系统既能正确处理图像，又能把原图、灰度、边缘、颜色掩膜和系统状态清楚、连续地显示出来。用户应能看懂“正在使用什么算法、目标在哪里、是否检测有效、云台在什么状态、标定是否已生效”。

这对应赛题二的图像处理、稳定显示、安路 Logo/OSD，以及多算法切换、跟踪信息标注和延迟可视化。不要只交几张效果图；要交 A 能接入、能复跑、能定位错误的 RTL 模块。

你已经交付的 B7 中，灰度、Sobel、按钮、四模式、静态 OSD 等代码继续复用。现在主要工作是接真实识别数据和当前板级链路，不要求从零重写。B7 的完整顶层独立验证通过，不等于已在 H4E 上板；以前 H1/H2 用过你的旁路/灰度模块，H4E 使用了你提供的 Logo ROM。

## 三、分阶段执行；每阶段通过再叠加

### B0：复现现状，先知道什么已经通过

**目标：** 在你的电脑重现共同基线，明确 B7 与当前板级显示路径的差别。

在仓库根目录执行：

```powershell
python -m pip install -r boards/hx1p35a/h4e/requirements.txt
python -X utf8 boards/hx1p35a/h4e/run.py check
python -X utf8 boards/hx1p35a/h4e/run.py unit
python -X utf8 boards/hx1p35a/h4e/run.py pipeline
```

Python、`iverilog`、`vvp` 需要在环境中可用。共同回归应得到 216 来源文件校验通过、68 个区域案例通过、13 帧完整 720p 链路通过。然后按 B7 自带说明复现你负责的显示测试。

**交付：** 一份复现记录：使用的 commit、工具版本、命令、退出码、PASS摘要；列出你准备提取的 OSD 模块和接口差异。此阶段不改算法、不接按键、不修改画面布局。

### B1：先接动态框与文字，让显示内容可信

**目标：** 接收 C 的一份完整结果，在正确位置画框、中心十字和目标信息。先保持 H4E 已验证的显示行为，再单独做布局优化。

建议拆成两个 PR：B1a 只做整包快照、目标框和十字；B1b 再加入动态文字与诊断。Logo 在两步中都保留。

你需要完成：

1. 接收 `result_strobe`、有效性、frame_id、cfg_id、中心、四边坐标、面积和原因码，按一次事件锁存整份结果。
2. 在约定的显示帧边界更新显示快照。不能一帧画到一半突然换框，也不能新 X 配旧 Y。
3. 有效时画被选中目标的框和中心；无效时清除框/十字，并显示对应状态。
4. 正确裁剪画面边缘，避免无符号减法回绕。目标框经过 Logo 时，Logo 不透明像素保持完整。
5. 区分“有目标”和“云台正在跟踪”：机械状态由 A 提供，不能根据 `target_valid=1` 自己显示“闭环跟踪成功”。

**必须提交的仿真场景：**

| 输入场景 | 自动验收结果 |
|---|---|
| 假结果框为x100..199、y200..299，中心149/249 | 边线和中心按声明的线宽/十字尺寸出现在期望像素，参考图一致 |
| 有效结果在显示一帧中途到达 | 本帧仍使用旧快照，下一约定边界整包更新 |
| 下一结果无效，几何为零 | 新快照后无绿框/目标十字，不在左上角画假目标 |
| 框贴四边、接近角落、包含越界绘制请求 | 不回绕到对侧；有效画面外不绘制 |
| 框/十字经过Logo | Logo不透明像素与原ROM一致 |
| 复位、帧中断、ID或配置不匹配 | 不混用两帧字段；按接口产生无效/等待行为，恢复正常 |

**交付：** RTL、TB、假结果序列、独立像素参考、实际 RTL 输出图和差分图、自动断言日志、延迟说明、资源报告。结果示意图必须来自 RTL 输出，不能只交参考模型画的图。

**注意：** 当前 H4E 用前一个完成刷新的结果画框，本来可能有一帧左右滞后。后续按真实源帧匹配，还是显示带来源/年龄的最新结果，需要与 A 在适配配置中写清；不能只把端口改名就声称同源帧对齐。

### B2：先对齐真实数据，再逐个接入显示模式

**目标：** 同一位置的 RGB、滤波 mask 和边缘像素必须对应同一图像，且最终能按 HDMI 节奏输出。

这一步最容易出现“仿真画面看起来像对了，上板却错位”。C 的滤波会缓存行、补边界、改变输出节奏，不能假定给 RGB 或 HS/VS 延迟几拍就完成对齐。

按以下小步交付，每次只增加一项：

| 小步 | 需要完成 | 验收重点 |
|---|---|---|
| B2a | 接真实 C 滤波模块；同坐标/源ID的RGB与mask配对 | 逐像素检查x/y、帧ID、cfg、SOF/EOL/EOF，无错配、无丢像素 |
| B2b | 接RAW，再接GRAY | 用已知色块/灰阶验证像素；同步、边界和延迟不被模式破坏 |
| B2c | 接EDGE | 与独立Sobel参考逐像素比较，明确阈值、边界、位宽/截断规则 |
| B2d | 接MASK，再接四模式联合路径 | 不能继续用棋盘测试mask代替真实C输出；模式对应关系正确 |

最低联合场景使用 1280×720 有效图像、1650×750 总光栅。包含多个连续帧、黑白/颜色块、贴边目标、移动/消失目标、行间消隐、上一帧尾部冲刷时下一帧进入、运行中复位。合法输入范围外的不足/中断用例必须按契约显示错误并可恢复，不能静默输出旧数据。

**验收与交付：** 自动比较输出像素、坐标、帧标记和身份；检查正常序列 FIFO 溢出/欠读为0，记录峰值占用；故障注入能触发对应状态。提交输入/输出时序图、FIFO深度计算、缓冲方案、完整720p日志、图像差分、源列表、资源报告及给A的接入说明。

**资源注意：** B7 原独立综合28 ERAM，其中RGB对齐FIFO占23。不能只说“仿真通过”而不解释缓冲大小，也不能直接加一份整帧缓存。整板当前45 ERAM已包含部分功能，新占用由完整工程决定，不能机械地把两个工程的数字相加。优先保存必要数据、共用可复用缓存，向A说明新增/替代了什么。

**边界：** B7顶层是内部像素流，并非完整HDMI控制器。A负责最终显示定时/DDR供数；B负责交代输出节奏和缓冲需求，双方联合仿真。显示RAW/GRAY/EDGE/MASK不能改变送C的原始彩色检测输入。

### B3：按键与状态交互，不能半帧切换

**目标：** 用户每按一次发生一次明确操作；画面标签反映已经生效的模式和配置。

1. 共用一份按键同步/消抖模块；A给实际时钟、极性和引脚。输出模式、标定、跟踪启停事件，A路由到对应模块。
2. 默认短按一次一事件，长按不连发；模式0原图、1灰度、2边缘、3掩膜。
3. 模式在有效SOF边界切换；请求与SOF同拍时，新请求留待后一个SOF。mode标签与对应像素一起传递。
4. 显示C的采样中、计算完成/失败、参数待应用、已生效状态；显示A发布的关闭、重获确认、跟随、丢失/超时保持及故障状态。

**仿真验收：** 抖动、按下长度略短/等于/略长于实际消抖门槛、长按、释放、连续按下、复位；模式请求与SOF同拍、快速多请求、非法值。实际默认消抖计数也要测试，不能只把参数改成4周期跑一下。

标定应显示中央16×16 ROI，720p为x632..647、y352..367。不要拿当前黄色256×256诊断ROI替代。`sample_done`只是采样结束，`calibration_done`只是参数计算结束，`cfg_applied`才是配置已生效。失败时显示失败并保持原活动参数。

**交付：** 按键/模式TB、实际计数边界日志、交互时序、状态映射表、RTL输出截图及资源变化。A负责逐模式上板确认，不一次同时改变按钮、标定和控制算法。

### B4：性能与延迟显示，以及最终联合回归

**目标：** 显示真实测量结果，让评委能看到实时性；没有测量值时诚实显示不可用。

A提供真实来源帧率、显示刷新率、结果率、延迟值及测量类型、异常计数；B负责显示数值、单位、有效标记和窗口统计。使用统一接口，不把`N=010000`当帧率，不把EOF到识别结果的时延写成采集到显示时延。尚无A数据时先用假数据验证显示，并明确“仿真输入”。

**验收：** 零值、最大显示值、无效值、更新同拍、计数溢出显示策略、帧中字段稳定；Logo始终完整。最后与真实C模块做720p联合回归，包含移动/消失、模式切换、配置切换、复位和容量失败恢复。

**交付：** 性能OSD模块、字段与单位表、参考图、联合日志、资源增量和板测观察清单。长期稳定/光照变化由A组织，B分析显示错位、FIFO和输出调度问题。
