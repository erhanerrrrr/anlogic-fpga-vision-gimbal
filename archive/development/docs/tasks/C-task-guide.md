# C 同学任务书：颜色识别、主目标定位与标定

版本：2026-10-10；起点：H4E 已验收视觉定位基线，代码提交 `7eb4a90`。本文件可以单独发给 C 阅读。A 负责板卡、来源帧身份和云台；B 负责图像显示与交互。

## 一、你的目标是什么

你的最终目标是：从一幅图像中可靠地找出当前要跟随的颜色区域，输出一份可用于画框和控制的完整结果，并支持分阶段完成颜色标定。

结果要回答：“有没有合格目标、在哪里、有多大、来自哪幅图像、使用哪个配置、为什么拒绝”。A决定云台怎么动，B决定画面怎么显示。你不需要再写一套云台死区、限速或机械丢失保持状态机。

这对应赛题二的目标检测、坐标/跟踪信息、稳定性及资源优化；颜色标定也是本项目简介承诺的功能。现在优先接管H4E、统一结果、接标定，不盲目追加复杂算法。

## 二、已有代码做到哪里，你应从哪里继续

## 三、必须继承的当前算法规则

| 项目 | H4E当前规则 | 注意事项 |
|---|---|---|
| 输入位置 | 固定白平衡后、Gamma/灰度/OSD前的RGB888 | 标定与检测必须看同一份RGB；不能拿拍屏颜色算阈值 |
| 红色条件 | R≥24、R−G≥16、R−B≥16 | 差值按有符号扩展计算；默认值不同于原C的80/40/40 |
| 边界保护 | 检测屏蔽上下各4行 | 不丢像素valid/坐标；上游残留根因仍待A定位 |
| 去噪 | 3×3中至少5个前景点；输出完整光栅边界 | 屏幕当前显示原始mask，检测使用滤波mask |
| 选区 | 8邻域连通区域中面积最大者 | 斜向接触也算连接；同色物体粘连时可能成为一个区域 |
| 接受门槛 | 选中区域面积≥256 | 面积是滤波后前景点数，不是框的宽×高 |
| 等面积 | 先ymin较小，再xmin较小 | 保持结果可重复 |
| 中心 | 包围框中点向下取整 | 非面积质心；target_id是颜色ID，不是物体身份ID |
| 资源/容量 | 64游程/行、128工作记录，逐行回收 | 不是整帧只能有128个区域；不能简单扩大寄存器阵列 |
| 填充率 | 用于诊断，不用统一75%门槛拒判 | 倾斜目标可能填充率低但完全有效 |

## 四、逐阶段任务与验收

### C1：先接管H4E回归和资源边界

**目标：** 证明你能复现当前已经通过的算法，并知道它在哪些情况下接受、拒绝和恢复。

在仓库根目录执行：

```powershell
python -m pip install -r boards/hx1p35a/h4e/requirements.txt
python -X utf8 boards/hx1p35a/h4e/run.py check
python -X utf8 boards/hx1p35a/h4e/run.py unit
python -X utf8 boards/hx1p35a/h4e/run.py pipeline
```

应通过68个区域案例和13帧完整720p链路。理解独立SciPy 8邻域参考，不能以RTL自己的中间寄存器反推期望结果。后续修改根目录开发核时，测试源列表必须改为该开发核；只跑冻结快照不能证明你的新修改正确。

**必须保留的检查：**

| 场景 | 期望 |
|---|---|
| 输入区域核的空mask | 新无效结果，E=1，面积/框/中心为0 |
| 直接输入区域核的15×17块 / 16×16块 | 面积255拒绝E=2；面积256接受E=0 |
| 从RGB/去噪前输入16×16实心块 | 不能沿用“256一定接受”：3×3滤波可能去掉四角，面积变252，应按滤波参考判定 |
| 一个大区域和远处小点/小块 | 只选最大合格区域，小块不把其框拉大 |
| 大目标移走，小目标仍≥门槛 | 下一结果选剩余小目标；清空后无效，重新放入恢复 |
| 等面积上下/左右两个目标 | 按ymin、xmin规则选择 |
| 斜向接触、孔洞、L形、分叉后合并 | 与独立8邻域参考一致，不能被固定填充率误拒绝 |
| 33分支、主目标加33/153/1216小块、先后结束的多区域 | 不再因累计临时编号耗尽而间歇失效，已测合法范围内正常选择 |
| 64/65游程边界、工作记录压力 | 边界结果与参考一致；超限显式E=3，不发布截断后的假有效框 |
| 人为不足的行处理时间 | E=5；之后合法帧能恢复 |
| 帧中复位、新SOF打断、valid间隙 | 按局部流契约恢复，不混入上一帧统计 |

**交付：** 复现日志、规则理解说明、容量/延迟/资源记录和最小失败场景（如发现问题）。没有真实失败证据时不重写算法。

### C2a：整理一个完整的主目标结果包

**目标：** A和B都消费同一份T主区域结果，不再有人误用F全局框。

保留以下字段：单拍`result_strobe`、`target_valid`、32位frame_id、16位cfg_id、2位颜色ID、20位area、各11位中心/四边坐标、3位reject_reason，以及区域数/峰值工作记录诊断。`capture-v1`适配还需保留32位capture_epoch。具体名字映射见统一接口。

一次事件锁存整包。无目标也有结果事件，并清零公开几何；没有事件时保持字段不表示“来了新帧”。当前E=0有效、1空、2面积小、3容量、5超时/保护；E=4由显示适配层表示快照未就绪/不匹配，不是区域核输出。

**仿真验收：** 有效→空→有效；有效→容量错误→恢复；连续结果；结果前后配置/帧身份正确；复位清空；输出strobe宽度正确；字段不会混帧。给A/B一份确定的假结果序列，包含期望事件次数和全部字段值。

**交付：** 结果封装RTL、显式源列表、TB、字段表、示例结果CSV/小型JSON、资源增量。先不接标定，不改选区规则。

### C2b：接新来源帧语义，防止把旧图像当新观察

**目标：** 同一张摄像头图像重复显示多次时，只产生一次新的控制观察。

A负责实际完整帧提交、DDR槽与ID绑定、capture_epoch、CDC和超时；C负责在像素到结果的处理中保存身份，并对连续重复来源身份抑制新通知。没有真实ID时，先用假ID验证，不能把H4E刷新计数换个变量名就当任务完成。

**必须测试：**

| 输入序列/操作 | 期望 |
|---|---|
| 来源ID 10、10、11 | 新观察依次为1、0、1；重复显示不重复推动控制 |
| 同一ID重复，但外部请求改阈值 | 重复图像不成为物理新观察；配置等下一新来源帧应用 |
| FFFFFFFF→00000000 | 正常回绕仍是新帧 |
| 相机局部重启，frame_id重复、epoch变化 | 区分新旧来源，不误丢新帧或接纳在途旧结果；与A的复位协议一致 |
| 停止送入完整帧，时钟继续 | 已完整输入的最后帧可有限冲刷完成，之后不凭空产生新观察；保持valid不能代表新鲜 |
| 中断半帧再恢复 | 不将两帧拼成一个有效结果，恢复后身份/几何正确 |

现有去重只覆盖连续重复，不保证任意旧帧重放检测；A保证顺序。C不自行编造时间戳，也不把“无目标”当成“没有新数据”。无目标的新帧应通知A，由A执行保持/重获策略。

**交付：** 身份传递与去重适配、假来源帧驱动、自动断言/事件统计、和A的接线说明。B也使用该包，不另起一份不同口径的位置数据。

### C3a：颜色标定第一步——只采样，不改阈值

**目标：** 用户把色卡放入小框并请求采样后，获得正确的ROI颜色统计。

ROI为中央16×16，720p坐标x632..647、y352..367，共256像素。请求等下一合格的新来源帧执行。输出count、各通道sum/min/max/mean及sample_done；此阶段检测阈值仍保持原值。

**验收：** 均匀色块均值应等于输入；人为构造渐变/两色图计算独立统计；ROI边界像素包含规则一致，外部像素不计入；忙碌请求、复位、采样中断、重复源帧均有明确行为。count必须能表示256（不能只有8位）；单通道总和最大65280，算术不能溢出；均值舍入规则写清。

**交付：** 采样模块/TB、独立统计参考、ROI和请求时序、结果示例。不要此时就接自动改阈值，以免出问题无法判断是采错颜色还是参数生成错误。

### C3b：第二步——判断样本并计算候选参数

**目标：** 判断本次样本适不适合标定；合适则给候选颜色/阈值，不合适则说明失败。

复用并审查现有C9计算。测试均匀红/绿/蓝、灰色、混色、过暗/过亮、均匀度门槛及算术限幅。阈值规则要与当前检测入口颜色范围相符，不能未经真实输入确认就把原80/40/40默认配置带回来。

**验收：** 与独立整数参考一致；边界值前后各有用例；成功/失败状态与原因正确；失败或参数尚未应用时活动阈值不变。此步骤输出`calibration_done`及成功标记，不得把它当`cfg_applied`。

**交付：** 规则说明、参数化RTL、软件参考、候选值及失败原因样例、自动对比日志和资源报告。

### C3c：第三步——新参数在一帧开始时整体生效

**目标：** 同一幅图像从头到尾使用同一套参数，不出现上半帧旧阈值、下半帧新阈值。

参数先进入pending，在下一真实新来源SOF整体应用，cfg_id递增，发单拍cfg_applied。待切换期间旧帧仍携带旧cfg；生成参数恰好遇SOF时该帧继续用旧配置。

沿用C9交互约定：busy包括等待/采样/计算/待应用；busy中额外请求忽略不排队；标定与人工选色同拍时标定优先；完成/应用同拍请求仍忽略，下一拍才可接新请求。失败保留旧配置。

**验收：** 帧中请求、SOF同拍生成、重复来源帧、忙碌竞争、人工选色、cfg_id回绕、复位、在途上一帧；逐像素探针证明帧内参数不混用，结果的cfg与实际使用参数相符。先用红色24/16/16、当前基线配置复现既有结果，再评估新标定效果。

**交付：** 参数控制/应用适配、联合TB、逐帧参数与结果日志、与B共享的状态事件示例、A上板步骤。必须按C3a→C3b→C3c三个小阶段交付。

### C4：真实像素回放与环境鲁棒性

**目标：** 把上板问题变成电脑上能重复跑的测试，量化误报、漏检和定位误差。

A提供检测入口RGB888完整帧，逐行、每像素R/G/B三字节，无行填充；720p每帧2,764,800字节。元数据应有来源ID/epoch、cfg、活动阈值、入口位置、bit哈希、曝光/光照说明及人工目标标注。条件不足时先交回放工具和合成数据测试，不捏造实拍结果。

先证明软件参考和RTL一致，再与人工标注比较真实效果。两者不是一件事：错误阈值的软件和RTL也可以完全一致。保留倾斜、反光、暗背景、亮暗切换、贴边、多同色目标、接触粘连、空场和停帧等场景。

**验收与交付：** 输入格式校验、文件回放TB、固定种子/数据哈希、实际RTL结果、独立差分、错误分类和样本分母。帧级误报/漏检与像素级指标分开；拒判E=3/E=5不能默默当作“场景无目标”。每个新失败场景尽量缩小后加入回归。

## 五、资源与交付纪律

当前已验收整机为12,348 Slice、45 ERAM、8 DSP。每次改动报告模块资源和预期整机增量，由A跑完整工程确认。区域记录优先保持RAM和共享运算结构；不要简单把数组扩几倍，不随意增加整帧缓存。给出行处理时间、容量和超限恢复行为，不能只给平均速度。

每个PR必须包含前置commit、目标、接口profile、源列表、RTL/TB、独立参考、数据生成器、命令/版本/退出码/PASS摘要、资源/延迟、已知限制、A板测步骤和失败需回传字段。大波形/逐像素文件由脚本生成，不全部塞入仓库。

“冻结基线仿真通过”“开发版本仿真通过”“独立综合通过”“A整机上板通过”分别记录。固定的显示刷新ID与真实采集帧ID不能混写；H4E可变结果延迟不能套用旧C10的W+7周期。
