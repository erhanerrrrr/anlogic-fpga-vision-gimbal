# C端交接：识别、定位与颜色标定

2026-10-06。交付范围为C端本机验证。B显示RTL和FPGA检测入口实物数据目前未提供；与B联调、H3静态视觉、H4云台闭环均待后续完成。

## 先运行什么

解压交付包后，在`fpga_c_delivery`目录打开PowerShell。需要Python 3.7或更高版本、ModelSim的`vlib/vlog/vsim`在PATH中；TD综合另需安路TD 6.2系列。Python脚本不依赖第三方包。

```powershell
python scripts/run_c10.py
python scripts/test_c_capture_analysis.py
python scripts/run_c10_td.py
```

重跑全部阶段：

```powershell
python scripts/run_c_acceptance.py --td
```

这些命令正常应退出0。故意错误自检`python scripts/run_c10.py --check-only --inject-error`应退出1，它证明中心坐标差1会被检查器发现。仿真可能需要数分钟，主机运行耗时不代表FPGA处理速度。

便携包省略大型掩膜二进制；使用`--check-only`前应先运行一次完整C10，重新生成这些文件。

工具在ASCII临时目录运行，减少旧版软件遇到中文路径的问题。交付包里的`DELIVERY_MANIFEST.json`记录文件SHA256；生成物可重新创建。源码通过项目GitHub仓库同步，板级及B联调状态以本文件记录为准。

## 接入哪个模块

最终完整顶层是`rtl/recognition/rgb_calibrated_result.v`，源文件列表是`rtl/recognition/c10_sources.f`。C10继续使用C9验证过的RTL，不另复制一套识别算法。

| 输入 | 接入约定 |
|---|---|
| clk、rst_n | 同一个像素时钟域，低有效异步复位；各时钟域同步释放复位 |
| pixel_valid、rgb[23:0] | 每有效拍1个RGB888像素，R在23:16，G在15:8，B在7:0，无反压 |
| x/y[10:0] | 左上角(0,0)，逐行递增；默认1280×720 |
| sof/eol/eof | 分别与首像素、行末像素、帧末像素同拍，空白期为0 |
| source_frame_id[31:0] | 采集来源ID，重复显示保持同一ID；最大ID后回到0 |
| calibrate_req | 同步单拍标定请求；先把色卡覆盖中央16×16区域 |
| color_select_req / color_select | 同步单拍人工选色，0红、1绿、2蓝；恢复该颜色80/40/40默认阈值 |

检测和采样使用同一份RGB，建议固定白平衡后、Gamma/OSD前。A必须核对厂家工程里的真实信号语义，不能只改端口名称。合法输入行内连续有效，行/帧间可以有空白。当前顶层不处理异步按键、不做跨时钟队列、不恢复HDMI时序。

默认ROI为x=632..647、y=352..367。改变输入尺寸或ROI需重新编译；ROI固定16×16且必须完整位于输入范围。B显示ROI框时使用同一坐标系。

## B使用的显示掩膜

`filtered_valid/mask/x/y/sof/eol/eof/frame_id/cfg_id/target_id`一起传递。完整合法帧对应W×H个输出，包括被置零的外边界；重复显示的来源帧仍有完整掩膜。滤波EOF相对输入EOF延迟W+3拍。

掩膜不是未经延迟的输入RGB；B应按标签和有效信号对齐，而不是直接沿用原EOF。动态目标结果也不必与正在显示的来源帧相同，显示端应保留真实结果帧号/版本。

## A/B使用的目标结果

`result_strobe`为一次新观察事件；同拍锁存`result_frame_id/result_cfg_id/target_id/target_valid/area/cx/cy/xmin/ymin/xmax/ymax/reject_reason/debug_*`。没有目标也发新通知，公开几何值清0；原始统计保留在debug字段。

结果包保持到下次结果或复位。停帧时旧的`target_valid=1`可能继续保持，因此A只能在新strobe到达时更新观察时间，不能仅凭有效位认定摄像头仍在更新。机械丢失保持、搜索、重获确认、限位和舵机控制均由A负责。

只去除连续相同来源ID的通知，不处理任意历史重放。包围框中心向下取整；全720p滤波前参考中心为(639,359)，与A可能采用的控制参考点(640,360)要明确区分。RGB EOF至新检测通知固定W+7拍，1280宽为1287拍。

## 标定状态的三个事件

1. `sample_done/sample_ok`：C8的小框像素是否收齐，不代表颜色适合标定。
2. `calibration_done/calibration_ok`：C9是否生成了合格的新参数；成功时参数进入pending。
3. `cfg_applied`：参数已在新来源帧SOF实际应用；以此事件和`active_cfg_id`显示“已生效”。

busy包含等帧、采样、计算及等待应用。期间额外标定/选色请求忽略，不排队；同拍两类请求标定优先。完成/应用同拍请求也忽略，下一拍才可接受。这个行为与S0早期草案的“重复选色取最后值”不同，以C9接口说明为准，需A/B冻结。

合格颜色主通道均值80..224、比另外两通道分别高至少40，每通道波动不超过32。生成阈值为主均值减32、两项通道差分别减32。失败保留旧值；一套活动参数不等于为三种颜色分别保存了标定档案。完整原因码及版本规则见[C9](../stages/C9.md)。

## 实物数据怎么交给C

优先导出检测入口完整RGB帧：行优先、无行填充，每像素连续R/G/B三个字节，720p每帧2,764,800字节。建议同时保存采样帧及其前后各一帧，包含来源ID、cfg_id、人工选色、实际阈值、标定事件和目标结果。

复制`tests/fixtures/c10/capture_manifest_template.json`，填写输入信号位置、照明/曝光、距离、源码版本或提交号、bitstream哈希、真实时钟频率及每帧文件路径。模板里的示例ID/版本/阈值需替换成实际记录。目标图像还应人工标注是否有目标、框/中心；没有标注就不能计算真实漏检和定位误差。

```powershell
python scripts/analyze_c_capture.py D:/captures/manifest.json --output D:/captures/analysis
```

该工具是软件参考分析，不是RTL回放。它按记录的逐帧参数生成掩膜、候选结果及ROI统计；`new_source`只标记连续ID去重，不模拟C9请求状态机。结果CSV为每个输入帧的候选统计，重复帧的候选不应当成新观察。

`provenance`必须区分`board_input`、`ordinary_photo`、`synthetic`。普通照片和手机拍屏经过不同曝光、白平衡、Gamma或压缩，不能当作FPGA检测入口RGB，也不能用它们证明实物阈值有效。目前分析工具只用合成RGB验证，尚无实物数据分析结果。

如果暂时只能导出统计，至少提供256点的count/sum/min/max/mean、采样/结果帧号、cfg_id、活动/pending参数和原因码；这足以分析标定失败，但不能还原整帧掩膜或测量全图误检。

## H3/H4需要记录什么

| 指标 | 获取方式 / 分母 |
|---|---|
| EOF至结果延迟 | FPGA同域计数；周期数与实际时钟频率一起记录，时间=周期数/f_clk |
| 新帧处理率 | 单位真实时间内的来源新帧数和新结果数；重复显示不计新帧 |
| 固定相机定位误差 | 色卡静止且有人工标注，分别报告cx/cy误差，注明像素坐标与样本帧数 |
| 错误有效 | 无目标/干扰标注帧中误报有效数，分母为这些标注帧总数 |
| 漏检 | 有目标标注帧中无效数，分母为有目标标注帧总数 |
| 拒判 | 按原因统计次数，同时给总新观察数；拒判不自动等于算法错误 |
| 标定成功率 | 成功/总请求数，分别统计不同色卡、照明、距离及ROI覆盖情况 |
| 闭环表现 | H4由A执行，先单轴后双轴，记录丢失/重获、限位和抖动；软件仿真不能替代 |

没有实测时以上硬件指标写“待上板”。TD报告只是综合资源估计，测试读出外壳未分配管脚、未布局布线、未时序签核，不能直接作为上板工程。

## 适用范围

首版处理人工指定红/绿/蓝中的单个可信色块，其他颜色可同时出现。远离的同色块可被填充率拒绝；靠近的同色块可能合并后被当作一个目标，不保证选择最大色卡。3×3多数滤波会削除细线和小目标；颜色规则受曝光、光照和背景影响。没有时间平滑、目标身份关联或机械状态机。

首轮联调遇到问题，先回传原始RGB、状态和版本，定位最早发生差异的模块，再增加回归；不要只在末端调阈值掩盖输入时序错误。
