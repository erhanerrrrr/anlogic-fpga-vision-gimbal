# A/B/C 统一接口 v1（2026-10-10）

本文件是新集成工作的统一入口，不改变已验收 RTL。必须区分两个 profile：

- **`h4e-refresh-v1`：已实现、已板测的冻结基线。** 帧号为显示刷新号，固定红色/配置；没有舵机或标定事件。
- **`capture-v1`：下一阶段开发约定，尚未板级实现。** 使用真实来源帧、原子结果、配置与新鲜度保护。完成接口适配、仿真和上板前，不得把 H4E 标为该 profile。

旧 C10、B7 文档描述各自模块；有差异时显式编写适配层，不直接改端口名来假装兼容。未在此冻结的具体电气参数（时钟频率、按键管脚、舵机脉宽范围）由 A 根据实物记录，不能猜填。

## 1. 像素流：A → B / C

| 字段 | 宽度 | 语义 |
|---|---|---|
| clk / rst_n | 各1 | 同一模块在 clk 上升沿采样；现有模块低有效异步复位。A负责各域复位同步释放及共同清空 |
| valid | 1 | 有一个像素，无 ready/backpressure；mask=0 仍是有效像素 |
| rgb | 24 | RGB888：R[23:16]、G[15:8]、B[7:0]；检测入口固定WB后、Gamma/灰度/OSD前 |
| x / y | 各11 | 左上角(0,0)，向右/向下递增；当前1280×720 |
| sof / eol / eof | 各1 | 仅valid时有效，分别与(0,0)、(W−1,y)、(W−1,H−1)同拍；不得把场同步电平直接当SOF |
| frame_id | 32 | 必须同时声明profile；H4E为HDMI刷新号，capture-v1为完整源图像ID |
| cfg_id | 16 | 识别配置版本，一帧内不变，跟随像素和结果传递；不是时钟计数 |
| target_id | 2 | 颜色0红/1绿/2蓝/3非法；**不是物体身份ID** |

有效像素按行优先顺序，不丢黑像素。当前联合目标时序为1280×720有效区、1650×750总光栅；B的模式链要求行内连续。模块支持插空的范围以其局部契约和测试为准，不因此宣称整链支持任意间隙或零消隐。A最终确定时钟并报告周期到时间的换算。

H4E `display_raster_adapter` 在有效USER后才接收首完整刷新，按配置尺寸生成坐标与EOF，未实现物理坏行/坏帧输入检查。其 `O_video_rd_en=I_video_de` 保持原DDR请求节奏，不允许把滤波后valid反馈为DDR读请求。

配置变化不得改变在途像素所属配置；新的显示mode也必须跟随像素，不能从按钮的即时请求旁路到屏幕标签。

## 2. 掩膜：C → 定位 / B

`mask_valid, mask, x, y, sof, eol, eof, frame_id[31:0], cfg_id[15:0], target_id[1:0]` 组成同拍数据。C已有端口名为 `filtered_*` 时做一对一映射，不重建坐标。

- H4E原始分类结果用于显示，滤波结果用于定位；两者必须用不同名字。屏幕上少量白点不一定属于被选中的区域。
- H4E检测先屏蔽上下四行，再以3×3多数表决（至少5点）滤波，边界输出为零，仍输出整幅图像坐标。
- 滤波含行缓冲、边界冲刷，输出调度变化；**不能只延迟RGB、HS/VS几个周期就假定对齐**。B要用同一坐标/帧ID的RGB和真实C掩膜配对；A负责最终HDMI定时和供数。
- 现有C5参考：RGB入口EOF到滤波EOF为W+3周期；C10旧全局结果通知为W+7。H4E最大区域结果是可变延迟，不能沿用1287周期作其固定延迟。
- H4E行引擎应在下一输入行结束前完成前一行；无反压，超限拒判。当前测试最大1007周期/行、EOF等待4周期只是已测场景。

## 3. 结果包：C → A / B

现有H4E生产者 `h4e_region_select`，端口到统一字段映射如下：

| 统一字段 | H4E端口 | 宽度 / 规则 |
|---|---|---|
| result_strobe | result_strobe | 单拍事件，接收者同拍锁存整包 |
| target_valid | target_valid | 该结果的目标有效性；保持高不代表持续产生新观察 |
| frame_id / cfg_id / target_id | result_frame_id / result_cfg_id / result_target_id | 32 / 16 / 2 |
| area | area | 20，无符号；选中滤波区域像素数 |
| cx / cy | cx / cy | 各11，floor((min+max)/2)，不是质心 |
| xmin / xmax / ymin / ymax | 同名 | 各11，包含两端的闭区间 |
| reject_reason | reason | 3，按下表解释 |
| peak_slots / component_count | labels_used / components | 8 / 12；诊断，不是控制指令 |

无效结果仍有事件和ID，公开area/坐标必须为零；零值不能当成“目标位于左上角”。结果字段保持到下一次事件或复位，接收者不得每时钟反复消费。

| H4E原因码 | 意义 |
|---|---|
| 0 | 有效，最大8邻域区域面积≥256 |
| 1 | 空帧/没有滤波后候选 |
| 2 | 最大区域面积不足256 |
| 3 | 游程或工作记录容量超限 |
| 4 | **显示适配层保留**：快照未就绪/编号不匹配；区域核不输出此码 |
| 5 | 行处理超时或根查找保护 |
| 6、7 | 保留 |

容量固定：64游程/行、128工作记录，逐行回收，不是整帧最多128目标。区域数12位饱和于FFF；发生容量/超时错误时计数无效，C=000不表示没有前景。原C6/C10拒判码及填充率规则不是本表语义，不能未经适配直接替换。

绿色框/青色十字只用T选区结果；R原始全局、F滤波全局、D对F算的填充率留作诊断。两物体的全局框可以很大，而T应只选择最大区域。禁止恢复统一75%填充率门槛。

## 4. 真实来源帧与控制新鲜度（capture-v1，待实现）

A负责完整帧提交、缓存槽及metadata绑定：只有可供读取的完整帧才成为新来源帧。读到哪份图像，就携带该图像ID；相机正在采集的新计数不能贴到旧缓存上。重复显示同一帧必须保持来源ID。

A增加 `capture_epoch[31:0]` 作为相机重新启动/来源复位的代次，与 `frame_id[31:0]` 合成来源身份。epoch由未被相机局部复位清零的系统域维护；整机复位时所有消费者与缓存共同清空。frame_id正常32位回绕为新帧；局部重启不得让旧结果碰巧匹配。该sideband目前不在H4E/C10端口内，适配层必须保留至结果，不能丢失后宣称已实现。

C根据有效SOF锁存来源/配置，完成时原子发布。C现有新帧逻辑只抑制**连续相同ID**，不保证任意历史重放去重；A保证顺序，不重放更旧缓存。配置只在下一真实新源帧生效，不把“同一图像换cfg”算成物理新观察。

```text
图像来源：          K       K       K+1      停采集（显示仍刷新）
显示可绘制：        是      是      是       是
新的控制观察：      1       0       1        0
来源超时：          0       0       0        达到A配置阈值后1
```

A在系统时间基准下维护最后一次完整来源提交/新结果时间，独立产生 `source_timeout`、`result_timeout`。没有新事件时不能由保持的target_valid刷新计时器。超时/无效进入保持，恢复需可配置的新帧确认。复位、ID回绕、重复帧、采集慢于显示、半帧、来源停止/恢复均必须测试。

跨时钟多位结果和帧metadata用异步FIFO或请求/应答邮箱原子传输，不能每位单独两级同步。配置/跟踪按钮事件也需可靠跨域。A记录各时钟、约束与CDC覆盖。

## 5. B显示、按键与C标定

显示模式：0 RAW、1 GRAY、2 EDGE、3 MASK。显示分支不回流修改C的彩色检测输入。B7是内部像素流，不产生可直接替代HDMI的HS/VS；其RGB对齐FIFO、行尾冲刷与A的显示消费时序必须联合验证。FIFO峰值占用、溢出/欠读、输出调度与资源报告是交付项。

OSD在显示帧边界锁存整份结果，帧中不更新单独X/Y。H4E显示前一个完成刷新结果，可存在一帧左右的框滞后，不能冒称同源帧精确叠加。后续capture-v1必须标明采用“同ID帧匹配”还是“带来源ID与年龄的最新完成结果”策略；B实现前由A在集成配置中选择并提供测试，禁止静默混搭。Logo不透明像素优先于目标框/十字；其它图层不得遮挡正式Logo。

B维护一份同步/消抖模块；A提供管脚、极性和实际时钟参数，并路由 `mode_next_evt`、`calibrate_evt`、`track_toggle_evt`。v1默认按下一次一事件、长按不连发。模式请求等待下一有效SOF，请求与SOF同拍时新请求从后一个SOF生效；B现有模块若不同须适配/补测试，不能只改文档。

C标定拆为采样、参数生成、原子应用。ROI为中央16×16：720p的x632..647、y352..367，包含两端、共256点；这不是H4E黄色256×256诊断框。

事件沿用C9：`sample_done`表示采样结束；`calibration_done`表示计算完成（另有成功/失败）；`cfg_applied`才表示新参数已按新来源SOF生效。busy覆盖等待、采样、计算和待应用；busy时请求忽略不排队，标定与选色同拍时标定优先，完成/应用同拍请求仍忽略，下一拍才可接受。参数生成恰遇SOF则该帧用旧参数。失败保留旧值。

活动配置：`active_color[1:0]`、三个8位阈值、`active_cfg_id[15:0]`；H4E为红/24/16/16、cfg=1，而旧C默认80/40/40。C须参数化并先复现H4E，不得直接导入旧默认。cfg_id每次实际应用递增并自然回绕；与源ID/epoch配合使用。B显示真实active值和应用事件，不把采样完成显示为标定成功。

## 6. A控制与状态 / 延迟显示

A独占控制状态机，C只报告观测，B只显示。下一阶段控制参考点统一默认(640,360)，与包围框中点取整可能相差1像素是正常的；`ex=cx−640`、`ey=cy−360` 使用12位有符号值，仅新鲜有效结果时更新。安装方向、死区、限速/步长、软限位由A配置；PWM按舵机周期独立运行，不随像素/帧周期变频。

给B的状态编码约定：`tracking_state[2:0]`：0关闭、1等待重获确认、2跟随、3目标丢失保持、4来源/结果超时保持、5故障；6/7保留。另给每轴限位标志及 `pan_cmd_us[15:0]`、`tilt_cmd_us[15:0]`；没有编码器时名称必须为命令脉宽/命令角度，非实测角度。上述控制接口尚未在H4E实现。

延迟显示接口约定：`latency_valid`、`latency_us[31:0]`、`latency_kind[1:0]`（0采集SOF→显示SOF，1采集EOF→识别结果，2外部实测展示，3保留）。0和1须关联同一来源ID并在共同或已校准时间基准测量，包含哪些FIFO/DDR/处理/显示等待由A说明。2不可伪装实时内部测量。无数据显示N/A；按窗口给最小/平均/最大、样本数和单位。

## 7. 接口变更验收

字段、宽度、时钟、ID定义、边界事件或延迟调度变化，必须同一PR更新本文件/局部文档、适配层、两侧测试。至少包含：合法帧、空帧、帧中复位、SOF打断、边界/消隐、跨帧在途数据、配置切换、错误及恢复。OSD与真实C掩膜联合回归通过，才可把B的独立通过提升为整机通过。
