# C8：标定区域采样与统计

日期：2026-10-06；接口 c8-draft-1。仅实现采样，检测阈值仍为原有预设。公共接口待 A/B 确认，未上板。

## 本步做什么

在画面中央放一个16×16的小框。收到一次采样请求后，等待下一张新的完整来源帧，读取小框里的256个RGB像素，输出各颜色通道的总和、最小值、最大值和平均值。以后实际使用时，需要把色卡放到能覆盖这个小框的位置。

“采样成功”只表示完整收集了这256个像素；黑色、白色或混合色也可以采样成功。样本是否适合标定、生成什么阈值、何时切换参数，属于下一步 C9。

## 区域与给 B 的接口

ROI 是输入 RGB 图像中的固定区域，坐标从左上角(0,0)开始，边界包含两端。参数在编译时确定，不在画面中途移动。

| 参数 | 默认值 / 含义 |
|---|---|
| WIDTH / HEIGHT | 1280 / 720；当前支持16≤宽≤1280、16≤高≤720 |
| ROI_X / ROI_Y | (WIDTH−16)/2、(HEIGHT−16)/2，整数除法向下取整 |
| ROI宽高 | 固定16×16，不提供扩大参数 |
| 默认区域 | x=632..647，y=352..367 |
| 合法范围 | 0≤ROI_X≤WIDTH−16，0≤ROI_Y≤HEIGHT−16，必须完整位于画面内 |

B 绘制小框时使用相同参数与坐标系；若显示有缩放或裁剪，由 B 做坐标转换。本步没有修改 B 的显示工程，也未接原始按键。参数范围由集成方保证，测试脚本检查范围；RTL 不自动裁剪错误的参数。

新增独立核 `rtl/recognition/roi_color_sampler.v`，以及完整顶层 `rgb_sampling_result.v`。完整顶层将同一份输入 RGB 同时交给原 C7 检测器和采样核；采样不读取二值掩膜，也不会写识别参数。RGB接入位置沿用 S0 草案：固定白平衡后、Gamma/OSD之前，待 A 核实实际工程信号。

## 请求、忙碌与完成

输入为同一像素时钟域的 `sample_req` 单拍请求；异步按键同步、消抖由 A/B 负责。低有效异步复位，整机集成应同步释放。

1. 空闲时接受请求，`busy=1`，进入等待状态。当前正在输入的帧不采样。
2. 等待下一次有效 SOF，且该来源帧号与上一次见到的 SOF 不同，再开始采样。首帧0可接受，最大帧号回到0也可接受。
3. 请求若恰好与 SOF 同拍到达，该帧不采样，继续等待下一个新来源帧；重复显示同一来源帧不能绕过等待。
4. 采样帧开始时锁存 `source_frame_id/cfg_id/active_color`，在该帧有效 EOF 锁存统计并发一拍 `sample_done`，同时释放 `busy`。必须等 EOF，即使256个ROI像素已提前收齐，也不能提前报告成功。
5. 等待或采样期间的额外请求不排队、不重启。每个请求产生一拍 `request_ignored`，`ignored_requests`累计加1；16位计数到65535后保持，复位清0。若请求持续拉高，按每拍一个请求处理，因此上游应提供单拍脉冲。
6. 与完成同拍到达的额外请求仍按忙碌处理而被忽略；下一拍才能接受新请求。

新来源帧只按相邻 SOF 帧号是否相等判断，不保存全历史；任意乱序旧帧重放仍由上游管理。输入假设为已约定的逐行像素流，帧内配置固定。

## 输出字段

| 字段 | 位宽 | 含义 |
|---|---:|---|
| busy | 1 | 等待新帧或正在采样 |
| sample_done / sample_ok | 各1 | 完成事件 / 本次采样是否完整 |
| sample_reason | 2 | 0=完整，1=EOF时样本数不足，2=未到EOF就遇到另一个SOF |
| sample_frame_id | 32 | 实际采样的来源帧号；失败时仍指向被中断的帧 |
| sample_cfg_id / sample_target_id | 16 / 2 | 采样帧起始时使用的配置版本和人工选色 |
| sample_count | 9 | 区域内有效像素数，成功固定为256 |
| sum_r/g/b | 各16 | 通道总和；合法最大256×255=65280 |
| min_r/g/b、max_r/g/b | 各8 | 每个通道独立的最小/最大值，零样本时均为0 |
| mean_r/g/b | 各8 | 成功时为sum向右移8位，即向下取整的平均值；失败时为0 |
| request_ignored / ignored_requests | 1 / 16 | 忽略请求事件 / 复位以来的饱和计数 |

结果字段整体保持到下一次完成或复位。新请求不清除上一份结果；`sample_ok=1`本身不表示刚完成，应结合`sample_done`读取。采样失败保留已收集的计数、总和及极值作调试。

合法ROI固定256点，因此不需要除法器、大图像缓存或新增RAM。16位总和只对这个固定区域和合法光栅输入成立；以后扩大区域必须同步修改位宽和测试。

## 停帧、复位与失败边界

等待期间无新帧，或者采样期间像素停止而无 EOF，保持busy、不发送成功。这里没有墙钟超时；后续交互逻辑应处理等待提示和超时。复位丢弃半帧和待处理请求，清除结果，不产生完成事件；需要重新请求。

采样尚未结束就遇到另一个有效 SOF，报告被中断帧的失败结果，释放busy；不会自动用新帧重试。到EOF时只收齐255个ROI像素也报告失败。RTL不是通用光栅纠错器：不能保证发现所有“重复一个像素又丢一个像素”等非法流，合法坐标/帧标记仍由公共输入接口保证。

## 实际验证

独立Python参考先收集ROI完整像素列表，再用整数求和及min/max计算，和RTL流式累加相互核对。固定帧号锚点另行核对采样选择，不只依赖状态模型。

| 样本 | 实际统计 |
|---|---|
| 128点(144,40,40)+128点(160,40,40) | count=256；sum=(38912,10240,10240)；mean=(152,40,40)；min=(144,40,40)；max=(160,40,40) |
| ROI外全部改亮蓝色 | 上述全部统计保持一致 |
| ROI全255 | 每通道sum=65280，min=max=mean=255，无溢出 |
| 通道各遍历0..255的非均匀样本 | 每通道sum=32640、min=0、max=255、mean=127，验证向下取整 |
| 纯绿/纯蓝样本 | 平均分别(40,152,40)、(40,40,152)，验证通道顺序 |
| 全黑样本 | 完整采样成功，所有数值为0；未因此批准颜色标定 |
| 缺少最后一个ROI样本 | count=255，失败原因1，均值清0 |
| ROI已收齐但未到EOF就遇到新SOF | count=256仍失败，原因2，不把半帧当完整成功 |

三组测试：32×24请求协议、16×16整帧即ROI的首末像素边界、5帧完整720p图像。共逐拍比较4,701,703周期；15次采样完成中13次成功、2次预期失败。等待/采样中重复请求、请求与SOF/EOF同拍、重复帧、帧号回绕、停帧、复位、忽略计数饱和都通过。

每拍把C8顶层的全部检测和掩膜输出，与并行的原C7顶层直接比较，差异为0；本轮还重新运行C7独立去重及完整链路回归并通过。前面C1–C7源文件未修改。

采样结果在输入EOF被采样的同一上升沿寄存更新后可见，接收方在下一边沿读取；无需等待原检测流水线。检测通知延迟仍为W+7拍，采样通知和检测通知不能视为同一事件。仿真时钟拍数不等于实测板级速度。

运行：

```powershell
python scripts/run_c8.py
python scripts/run_c8.py --check-only
python scripts/run_c8_td.py
```

检查器故意错误自检：`python scripts/run_c8.py --check-only --inject-error`应退出1，证明统计总和差1会被发现。干净目录复测只复制必要源文件，重新编译和仿真；结果记录见验收报告。
