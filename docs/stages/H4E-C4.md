## 做了什么

- `scripts/replay_h4e_rgb.py` 校验 manifest、RGB/标注文件长度与哈希、入口位置、来源身份、配置和标注；通过后读原始二进制 RGB 文件进入真实 RTL。
- `sim/h4e_c4/tb_h4e_rgb_replay.v` 驱动现有 `h4e_capture_tracker`，R64 不变，完整经过分类、上下 4 行屏蔽、3×3 多数滤波、8 连通最大区域、结果封装和来源去重。每帧原始 RGB 完整读入，不跳过背景像素。
- 回放入口使用每帧已经实际生效的 cfg/阈值元数据。因此直接用 C2b 捕获封装，不重新执行 C3c 标定按钮流程；C3c 的控制时序测试仍独立有效。
- `model/h4e_c4_reference.py` 独立计算逐像素分类、滤波及 8 邻域洪泛区域。与 RTL 的两级掩码逐字节比较，再比较身份、cfg、有效性、拒绝原因、面积和边框/中心。
- 另用人工/合成几何标注计算帧级误报/漏检、bbox IoU、中心误差及像素 TP/FP/FN/TN。分类掩码和滤波掩码分别报告，不能混成帧级识别率。
- 每帧返回后留出 64 拍观察，最后额外停止输入 256 拍，确认没有重复结果事件；同一来源帧重放虽可有显示结果，但 new_observation=0，不重复纳入效果指标。

工具运行格式与 A 导出要求见 [RGB 回放接口 v1](../interfaces/rgb-replay-v1.md)。不会读取或执行元数据中的任何脚本指令。

## 合成效果指标与已知边界

scenes 集：去掉 1 次重放，剩余 16 帧；14 帧有目标、2 帧无目标。检出 10 帧、漏检 4 帧、误报 0 帧、正确空场 2 帧。因此本集合漏检为 4/14、误报为 0/2；样本是人为构造的压力场景，不能把比例当作实际现场性能。

|场景|本次表现|解释|
|---|---|---|
|均匀红/绿/蓝、倾斜、分离同色卡|预期目标被检出|仍按最大连通区域及既定同面积规则选择|
|强反光|漏检|白色区域失去主色优势，剩余红色区域太小|
|过暗、亮转暗|漏检|字节强度不满足当前 24/16/16|
|遮挡分裂|漏检|目标被分成多个不足面积门槛的区域|
|贴边|有检出，框被裁减|上下屏蔽/滤波边界导致 bbox IoU 约 0.781|
|两张同色卡相接|合为一个连通目标|相对单张主目标框 IoU=0.5，中心偏移 10 像素|
|彩色背景散点|无帧级误报|分类掩码有散点，滤波后被去除|

scenes 像素标注分母 49,152：分类掩码 TP/FP/FN/TN=6652/88/1752/40660；滤波掩码为 6488/0/1916/40748。合成 mask 来自生成时形状，并包括已知反光和遮挡区域，不是实拍人工分割。

TP 只表示“有目标时输出了一个目标”，并不代表定位正确；定位另报 IoU/中心误差。因此接触粘连案例不会被一句“检出成功”掩盖。当前算法没有承诺分开彼此相接的同色卡，本步记录限制，没有新增追踪/拆分算法或改动阈值。

## 错误分层与退出状态

1. 格式/哈希/输入配置错误：停止，不进入效果统计。
2. 软件/RTL 像素、几何或身份不同：停止，保存编译/仿真日志和像素首批差异位置（若为像素差异）。不得继续声称检测评估可信。
3. RTL E3/E5：作为 capacity_failure/deadline_failure 单列，排除普通检测率的分母，同时保留结构失败数量。若不是合成清单明确预期的压力拒绝，summary 标为 PASS_WITH_STRUCTURAL_FAILURES，独立 CLI 退出 2，提示回放完成但存在结构问题。
4. RTL/软件一致但标注不符：记录 false_positive/false_negative 或定位误差。这不构成硬件实现差分失败，但必须保留性能失败案例。
5. 无标注：只参与实现差分，不参与效果指标。重复来源帧：保留显示结果，排除重复指标。

指标自测额外注入误报和 E3，确认能区分两者，且 E3 不落入普通 FN/TN；无标注计数和接触目标定位误差也有断言。源数据有变化时哈希检查拒绝继续，避免错用编辑后的标注。

## 资源占用

**生产 RTL 没有任何修改，新增 FPGA Slice/ERAM/DSP 为 0；不需要为工具新增 TD 综合。** 原冻结/开发识别模块的资源、容量和行时间限制不变。

电脑侧不用 NumPy/SciPy 或额外依赖，只需 Python 3.12 和 Icarus。每次以一帧计算参考，使用 bytearray 掩码和 32 位整数栈，避免对整幅 720p 的每个像素创建坐标元组集合。仿真不生成大波形或逐像素 CSV；两级实际掩码各每像素 1 字节，比较后随临时目录释放。

临时数据约为每个像素 5 字节（RGB 副本 3 + 两级掩码 2），一幅 720p 约 4.39 MiB，另有小型编译文件与日志；这个数是磁盘数据量估计，不是 Python 进程峰值内存。一个数据集会暂存整组输入和掩码，较长序列应按明确重置边界分组，不要为了拆批伪造跨组连续去重。

合成集只保存生成器、manifest 小型快照与结果；RGB/逐像素数据在 ignored 目录生成。完整 720p 仿真可能明显慢于小图，应先验证一帧，再扩展数据集，超时不能当 PASS。

## 复跑和使用

仓库根目录：

```powershell
$env:Path='C:/iverilog/bin;'+$env:Path
./tmp/h4e-env/Scripts/python.exe -X utf8 scripts/run_h4e_c4.py
```

该命令生成 3 组合成数据、运行格式检查、真实 RTL 回放、独立差分及指标自测。单独使用：

```powershell
./tmp/h4e-env/Scripts/python.exe -X utf8 scripts/generate_h4e_c4.py
./tmp/h4e-env/Scripts/python.exe -X utf8 scripts/replay_h4e_rgb.py reports/h4e-c4/generated/datasets/scenes/manifest.json --validate-only
./tmp/h4e-env/Scripts/python.exe -X utf8 scripts/replay_h4e_rgb.py reports/h4e-c4/generated/datasets/scenes/manifest.json --output reports/h4e-c4/generated/scenes
```

真实数据将 manifest 参数替换为 A 的本机文件路径，输出保持与输入目录不同。默认每个编译/仿真命令超时 300 秒，可显式传 `--timeout-seconds`。输出 summary.json 是该轮状态入口；失败时不要拿上一次留下的 records/metrics 当本次通过。

结果文件：records.json 逐帧对照/错误类别，metrics.json 样本分母及指标，results.csv RTL 包，manifest_snapshot.json 输入说明，commands/日志/哈希为复跑证据。正式小型证据位于 `reports/h4e-c4/evidence/2026-10-10/`。
