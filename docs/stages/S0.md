# S0：C 的公共测试基础

日期：2026-10-05。状态：接口草案；C 的软件测试材料已建立，A/B 联合验收待完成。

## 当前范围

人工选择红、绿、蓝中的一种颜色。计划通过按键切换；按键处理由 B/A 提供，C 接收颜色选择请求。首次开发只承诺一张指定颜色色卡，允许其他颜色同时出现。多张同色卡的区分和选择留作后续增强，首版筛选不能保证识别所有歧义。

本阶段没有颜色分类 RTL、去噪、目标选择或板级改动。Python 对固定测试色值的计数仅用于验证样例，不能算作 C1 颜色分类验收。

## 公共接口草案 s0-draft-1（待 A/B 确认）

| 字段 | 草案 |
|---|---|
| clk / rst_n | 上升沿采样、低有效复位；时钟频率及复位适配由 A 确认 |
| pixel_valid / rgb[23:0] | 每有效周期一个 RGB888，R 在最高 8 位，无反压 |
| x / y | 左上角 (0,0)，向右/下增加；建议各 11 位，支持至少 1280×720 |
| sof / eol / eof | 与首像素、行末像素、帧末像素同周期，空白期为 0 |
| source_frame_id | 建议 32 位；采集帧编号，重复显示保持编号，最大值之后回绕到 0 |
| 输入位置 | 建议固定白平衡后、Gamma/OSD 前；A 必须核实实际工程信号和像素顺序 |
| color_select_req / color_select | 建议同步单周期请求；0=红、1=绿、2=蓝，3=非法并保持原值；默认红 |
| 颜色切换 | 请求暂存，下一完整新来源帧 SOF 生效；同周期才到的请求推迟。帧内不改变规则；重复请求取最后有效值 |
| 未来结果 | result_strobe、source_frame_id、cfg_id、target_valid、cx/cy、xmin/ymin/xmax/ymax、area、target_id，整体锁存 |

颜色切换和标定都应记录参数版本；细节在 C4/C9 前由团队冻结。跨时钟传递由 A 集成，不能把异步按键直接接入识别逻辑。

合法输入行内连续有效；行间/帧间有空白。本测试源每行 1～4 拍空白、每帧额外 2～8 拍，固定随机种子。这是模块测试时序，不是 HDMI 物理时序。以后 B 的 RTL 发生器应由独立检查器复核。

## 已建立的测试材料

`tests/fixtures/s0/cases.json` 存放矩形描述及人工独立计算的答案。数组顺序为 count,xmin,ymin,xmax,ymax,cx,cy；空颜色为 null。框含两端；中心向下取整。

- 红矩形：1271 点，框 (100,80)～(140,110)，中心 (120,95)。
- 下一帧同位置换绿，验证内容改变。
- 空帧与同时存在红绿蓝色卡。
- 两张红卡：原始整体统计中心落在中间，仅为能力边界样例，绝不标成可靠目标。
- 连续两帧 720p：第一帧只有末像素为蓝，第二帧全绿；各 921600 点。

生成器与检查器分开计算坐标；检查 RGB、坐标、标记、帧号、数量和独立几何答案。另用不同种子复查两帧 720p 的合法空白配置。循环有最大周期限制，失败返回非零。

运行：在项目目录执行 `python scripts/run_s0.py`。无需第三方 Python 包，支持本机 Python 3.7.8。输出为软件生成的 PPM 图片、小图像素流 CSV、summary.json；均不是 RTL 输出。

故意错误自检：`python scripts/run_s0.py --inject-error coordinate` 应返回退出码 1；还支持 rgb、marker、frame_id、truncated。正常运行应返回 0。
